The defect: gate.py took the mere presence of uv.lock / poetry.lock as the project's pin of a check tool and ran `uv run ruff`; for a lockfile that does not name the tool, uv starts whatever ruff is on PATH, so a global ruff of another version judged the change at Stop and formatted and linted at every edit.

The fix (.claude/hooks/gate.py): `tool_prefix(root, tool)` returns the lockfile runner for a tool only when the lockfile has a package of that name (`lock_names`: a line `name = "<tool>"`, as uv.lock and poetry.lock both write it); `check_tool` and `edit_ruff` ask it with the tool's name. Otherwise they fall through to what was already there: the project's virtual environment, then the engine's pinned lookup (PATH of exactly that version, else `uvx tool@version`, else the `tools/version` block; at edit time nothing is fetched and another version neither formats nor lints). `tool_prefix(root)` without a tool — the pytest prefix in check_steps — is unchanged: pytest is the project's. Not done: "the tool is in the project's environment" is judged as before by `.venv/` / `venv/` / VIRTUAL_ENV only (project_tool); a uv project whose environment lives elsewhere and whose lock does not name the tool now gets the engine's pinned version.
