## Що сталося
Задача 752 не закривається: `python3 .claude/hooks/mode.py check-close 752-open-item-overseer-stop-last-request-by-mtime` каже, що для commit-а `4814696` немає PASS overseer-а, «що бачив саме цей код», хоча PASS є (request `20261012T230250Z-7a8697`). Причина: між commit-ом задачі й audit-ом два з трьох його файлів змінив commit іншої задачі — `c61466c` (board 757): `.claude/hooks/overseer_verdict.py` (`c5e3f016f0f52c3e` у 4814696, `58882c71ca8e7758` у HEAD) і `tests/test_overseer_fresh.py` (`e5990c785759a9c8` → `c0096a0719b3fc3c`). `mode.unaudited` (рядок 410) порівнює вміст файла в commit-і з тим, що бачив PASS, і пробачає різницю лише тоді, коли файл пізніше змінив покритий commit ТІЄЇ САМОЇ задачі (задача 754). Перший audit 752 бачив саме той код, але записаний як BLOCK через чужу gate escalation; після відповіді власника код уже інший, тож жоден новий audit цієї перевірки не пройде. Те саме чекає на кожну задачу, що стояла в `blocked/`, поки інша задача міняла ті самі файли.

## Що зробити
Вирішити й збудувати в `mode.unaudited`: commit покрито також тоді, коли файл після нього змінив commit іншої задачі, а PASS цієї задачі бачив файл таким, яким він є після тієї зміни (тобто в гілці лишилось лише перевірене — той самий принцип, що в 754). Тести в suite check-close: (1) відтворення 752 — commit задачі, пізніший commit іншої задачі в тому самому файлі, PASS на дереві після нього → покрито; (2) негативний — PASS бачив дерево ДО чужого commit-а, або PASS немає → не покрито; (3) негативний — файл після PASS змінено ще раз → не покрито. Це зміна правила, яким власник відповів у 754 («б»), тож якщо бачиш розвилку — питання власникові. Після цього `mode.py check-close 752-open-item-overseer-stop-last-request-by-mtime` має бути зеленим без нового audit-у.
