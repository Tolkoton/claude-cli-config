## Що сталося
Задача 056 закрила файл ключа другої моделі в теці оператора: simplifier-key.sh тепер у SECRET_PATTERNS, і ні shell-команда, ні edit tool його не читають. Але runner перед стартом виконує цей файл і експортує ключ змінною GEMINI_API_KEY_SIMPLIFIER у своє середовище — видно в рядку запуску tmux-сесії engine-board. Кожна сесія, яку стартує runner, цю змінну успадковує, і агент читає її звичайною командою оболонки: env, printenv, echo. Hooks цього не зупиняють: читання змінної середовища не є читанням файла. Власник у сесії perimeter 2026-10-06: ключ не має бути видимим агентові і через середовище.

## Що зробити
Зробити так, щоб ключ читав лише сам скрипт другої думки (.claude/hooks/second_opinion.py) або hook, а не середовище сесії. Спершу проєкт рішення. Варіанти для нього: скрипт сам читає ключ із файла поза репозиторієм у момент запиту — шлях у змінній без самого ключа, файл із правами лише власника; runner не експортує ключ у середовище, з якого стартує claude, або прибирає його саме для процесу сесії; запит до другої моделі робить окремий процес runner-а поза сесією, а сесія лишає йому тільки запит-файл. Для кожного варіанта назвати, чи може агент дістати ключ іншим шляхом: /proc/<pid>/environ батьківського процесу, читання файла ключа скриптом, який агент сам напише. Оновити запис про SECOND_OPINION у project.env і .claude/references/simplifier.md. Тести: у середовищі сесії, яку стартує runner, змінної з ключем немає; друга думка при цьому працює; негативний випадок — без файла ключа скрипт каже no_opinion, а не падає.
