Аудит потрібен: ні

## Звідки
Повна проба /onboard на копії чужого проєкту (задача 057). Перед знайомством у копію встановлено
поточний двигун; там стояв старіший. Встановлення перенесло 19 записів зі старих шляхів
(`.claude/overseer/`, `.claude/premises/`, `.claude/architecture/`, `PROGRESS.md`) у `.engine/`. Наслідки:
- скрипти, файл для агентів і коментарі самого проєкту й далі вказують на старі шляхи;
- дві перевірки проєкту після цього виходять із кодом 0, нічого не перевіривши;
- перевірка форматування проєкту почала падати на трьох перенесених файлах: стара тека була у
  винятках форматувальника проєкту, нова — ні;
- /onboard про це нічого не каже: згадує старі шляхи як місце, де шукати записи, хоча їх там уже немає.

## Що зробити
Спершу проєкт рішення (коротко, у звіті), потім збудувати:
- **`engine.py install` / `update`**: після перенесення записів надрукувати `note` — які файли
  проєкту (не двигуна) ще згадують старі шляхи (пошук за рядком, з `file:line`), і чи нові шляхи
  покриті винятками lint / format проєкту, якими були покриті старі. Нічого в проєкті не правити.
- **/onboard**: окремий пункт огляду «що змінило встановлення» — `git status` на початку; записи
  шукати і за новими, і за старими шляхами; відмінність результатів перевірок, спричинену
  перенесенням, записувати як наслідок встановлення, а не як стан проєкту.
- **Шаблон профілю**: поруч із «Surveyed at commit» — місце для «дерево не чисте: N змін від встановлення».
- Перевірити на fixture: проєкт зі старими шляхами, скрипт, що читає старий шлях, виняток
  форматувальника на стару теку.

## Готово, коли
- `engine.py install --dry-run` на fixture друкує обидві примітки; тест падає без них.
- /onboard і шаблон профілю мають названі пункти; `tests/test_onboard.py` їх перевіряє.
