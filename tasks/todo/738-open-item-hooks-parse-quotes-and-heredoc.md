## Що зробити
Спершу проєкт рішення. Головне питання — що з процитованого тексту є лише текстом, а що оболонка виконає: тіло heredoc, поданого в bash, sh, python3 чи node, виконується; рядок після bash -c, sh -c, eval, python3 -c, node -e виконується; $(…) і зворотні лапки всередині подвійних лапок виконуються; аргумент для git commit -m, echo, printf, grep, board.py open-item --what — ні. Звідси правило: текст вважається лише текстом тільки тоді, коли команда, що його отримує, є у вузькому переліку тих, що тексту не виконують, і в ньому немає підстановок; у всіх інших випадках hook судить, як зараз. Один розбір для всіх трьох місць: block-dangerous.sh (push, змінна власника, DANGEROUS_PATTERNS), shell_paths.py і shell_readonly.py. Умова приймання: кожна форма обходу з наборів tests/test_shell_protected_paths.py, tests/test_push_hardening.py, tests/test_rules_file_protected.py, tests/test_overseer_readonly.py і tests/test_owner_perimeter.py лишається заблокованою — ці набори проходять без жодної зміни очікувань; golden set тотожний, крім нових сценаріїв. Нові тести з обох боків: процитований рядок у повідомленні проходить; той самий рядок у тілі heredoc для оболонки чи інтерпретатора, після -c, у підстановці — блокується. Окремо перелік зайвих відмов сесії 2026-10-06 як вихідні випадки. Задача змінює perimeter hooks, тому будується в сесії з власником.
