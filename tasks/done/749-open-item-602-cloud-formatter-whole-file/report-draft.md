# 749 — У хмарній сесії format-on-edit переформатовує весь файл: проєкт рішення

Нічого не збудовано. Платних прогонів не було.

## Коротко
Раджу варіант **Б**. У `.claude/project.env` двигуна ставимо `FORMAT_CMD="true"`, а в `gate.py` робимо так, щоб це значення справді вимикало будь-яке автоформатування, як і обіцяє коментар у `project.env` («To disable formatting: FORMAT_CMD="true"»). Сьогодні воно вимикає лише `.py`/`.sh`, а `.md` і далі переформатовує `prettier`. Це близько трьох рядків коду і тест. Встановлених проєктів зміна не зачіпає, бо вони отримують `project.env` із seed-шаблону (`.claude/ownership.txt:39`).

## Що відомо (перевірено)
- `gate.py` `format_file` (`.claude/hooks/gate.py:1097`): коли `FORMAT_CMD` порожній, він сам шукає formatter. Для `.py` — `ruff format` і `ruff check --fix --select I`, або `black`. Для `.md`, `.yml`, `.toml` — `prettier --write`. Для `.json` — `jq .`.
- `FORMAT_CMD` діє лише для розширень із `CODE_EXTENSIONS` (у двигуні `"py sh"`, `.claude/project.env:37`). Перевірено запуском з підставними `ruff`, `black` і `prettier`, які лише записують свої аргументи. З `FORMAT_CMD="true"` для `a.py` не викликано нічого, а для `a.md` викликано `prettier --write --log-level silent …/a.md`. Отже, один ключ проблему `.md` не закриває.
- У хмарному контейнері є `ruff` 0.16.8, `black` 26.5.1 і `prettier`. На сервері двигуна їх, судячи з файлів, немає: записи `.engine/bugs/` і задачі не відформатовані `prettier`-ом, а `.py` — `ruff`-ом. `jq` є і там, і тут.
- Файли двигуна не відформатовані `ruff`-ом. Тому в хмарі правка на 8 рядків у `tests/test_simplifier.py` дала diff 593+/149− (задача 602). `prettier` додав порожні рядки після заголовків і екранував `_` як `\_`.
- Тимчасовий обхід уже є в нічних prompt-ах: крок 0 перейменовує `ruff` і `black` на `.off`. `prettier` він не зачіпає, тому агенти пишуть `.md` скриптом.

## Варіанти
**А. Лише `FORMAT_CMD="true"` у `project.env` двигуна.** Один рядок. Закриває `.py`/`.sh`, але не `.md` (див. вище) і не `.json`.

**Б. А + `FORMAT_CMD="true"` вимикає автоформатування для всіх розширень** (рекомендую).
- У `format_file` значення `"true"` повертає одразу, ще до вибору formatter-а. Будь-яке інше значення `FORMAT_CMD` поводиться, як сьогодні.
- Тест у `tests/test_format_on_edit.py` (там уже є harness із підставними formatter-ами, що записують argv). З `FORMAT_CMD="true"` для `.py`, `.md` і `.json` не викликано жодного formatter-а. Правка одного рядка лишає diff в одному рядку. Без ключа автоформатування працює, як раніше.
- Наслідок, про який варто знати: у двигуні перестане працювати й `jq` для `.json` після Edit/Write — і на сервері теж. Зараз `jq` там переформатовує JSON, записаний інструментом Edit/Write. Скрипти, що пишуть JSON самі, цього не помітять.

**В. Автоформатування лише тоді, коли проєкт має конфіг formatter-а** (`[tool.ruff]` або `ruff.toml` для ruff, `.prettierrc*` для prettier). Змінює поведінку за замовчуванням для **всіх** встановлених проєктів: ті, що покладаються на ruff без конфігу, втратять автоформатування. Це рішення про продукт. Зараз не раджу.

**Г. Нічого не змінювати в репозиторії**, обходити кроком 0 нічного prompt-а. `.md` лишається незахищеним, і кожен агент мусить пам'ятати про скрипти.

- `tests/test_format_on_edit.py`: випадки вище.
- `.claude/references/hooks.md` і `docs/TEMPLATE-SETUP.md`: «`FORMAT_CMD="true"` — без автоформатування для будь-якого файлу».
