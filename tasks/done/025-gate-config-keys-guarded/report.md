# 025 — PROJECT_MARKER і CODE_EXTENSIONS під охороною воріт: звіт

## Що змінилось для власника
- Діру закрито. Якщо хід змінює значення `PROJECT_MARKER` або `CODE_EXTENSIONS` у `.claude/project.env`, ворота блокують — наприкінці ходу (`stop`) і перед commit-ом (`pre_commit`). Раніше такий хід проходив чисто: лінтер, типи й тести просто не запускались.
- Пройти можна одним способом: запечатаний контракт зрізу називає сам ключ — рядок `gate-allow: PROJECT_MARKER — <причина>` (або `CODE_EXTENSIONS`). Незапечатаний чи змінений після схвалення контракт нічого не дозволяє.
- Ці два ключі охороняються суворіше за решту. Причина, дописана в самому `project.env`, для них не діє; дозвіл контракту «на весь файл» теж не діє; дозвіл одного ключа не покриває іншого.
- Дозвіл, яким скористались, бачить наглядач: `gate_allows.py` показує його в запиті на аудит разом із причиною з контракту.
- Золотий набір: 7 нових сценаріїв, новий еталон `evals/baseline/linux-ubuntu-22.04/results-task-025.json` (148 сценаріїв).

## Демонстрація на хвилину
Тимчасовий репозиторій, `LINT_CMD` навмисно завжди падає. Хід міняє `mod.py` і ставить `PROJECT_MARKER="absent.toml"`. Вивід дослівний (скорочено до першого рядка причини):

```
$ python3 .claude/hooks/gate.py --layer stop
gate[stop] 2 finding(s), exit 2
  block .claude/project.env [bypass/config] the diff changes PROJECT_MARKER — it decides whether lint, types and tests run at all, and the work being judged may not decide that
  log   - [marker] absent.toml not found — lint, types and tests skipped
```

Та сама тека після того, як запечатаний контракт отримав рядок `gate-allow: PROJECT_MARKER — tooling arrives in the next slice`: вихід 0, без жодного рядка.

Повторити самому:
```bash
python3 tests/test_gate.py | grep -E "PROJECT_MARKER|CODE_EXTENSIONS"
python3 evals/run_hook_scenarios.py --engine-ref HEAD --only vs-bypass
```

## Відкладене
- **Сценарій `vs-bypass-without-marker` (задача 020) тепер блокується першою причиною «змінено PROJECT_MARKER»**, бо хід у ньому сам ставить маркер. Результат той самий (`block`), еталон тотожний, сценарій не чіпав. Те, що він доводив, — доданий `noqa` блокується й без файла-маркера — тепер тримає новий `vs-bypass-without-marker-committed`, де маркер закомічено до ходу.
- **Ловля порівнює з HEAD.** Зміна ключа, закомічена повз ворота (commit зі скрипту, коли git pre-commit hook не підключено), для наступного ходу вже не зміна. Записав у `docs/engine-limits.md`. Це межа всієї ловлі, не лише цих двох ключів.
- **`SOURCE_DIRS` і `CHECK_CMDS` не охороняються.** На лінтер, типи й тести вони не впливають, але від них залежить, чи хід викличе наглядача. Задача про них не просила; якщо треба — окрема задача.
- Черга уроків просить розбору (40 кандидатів, понад 30) — окремий протокол, цієї задачі не стосується.

## Рішення, які я ухвалив сам
- **Суворіше за інші ключі.** У задачі два речення: «так само як для інших охоронюваних ключів» і «пройти можна лише тоді, коли контракт зрізу прямо дозволяє». Для інших ключів досить причини в самому `project.env`. Я взяв друге речення буквально: для цих двох ключів — лише контракт. Якщо мали на увазі «точно як інші», це одна правка: прибрати `SCOPE_KEYS` і додати обидва ключі до `GATE_KEYS` у `gate.py`.
- **«Прямо дозволяє» = контракт називає ключ.** Дозвіл на весь файл (`gate-allow: .claude/project.env — …`), який діє для інших ключів, тут не проходить.
- **Не задано і порожнє — одне значення.** Прибрати з файла рядок `PROJECT_MARKER=""` — не зміна: усі, хто читає ці ключі, читають обидва випадки однаково. Без цього наявний сценарій `vs-simplify-signal-never-blocks` став би `block`, і еталон не був би тотожний.
- **Порівняння за значенням, без нормалізації.** `"py"` → `".PY"` означає те саме, але вважається зміною. Простіше і в суворий бік.
- **Дозвіл показується наглядачеві** (`gate_allows.py`) — задача цього не називала, але так уже зроблено для всіх інших дозволів контракту; без цього дозвіл ніхто б не читав.
- **Записав новий еталон** `results-task-025.json` і оновив посилання в `AGENTS.md` та `evals/README.md`, як у задачах 020 і 018.
- **Дописав про охорону** в `.claude/references/gate.md`, `docs/engine-limits.md` і в коментарі біля обох ключів в обох `project.env` (цього репозиторію і зразка). Значень ключів не міняв.
