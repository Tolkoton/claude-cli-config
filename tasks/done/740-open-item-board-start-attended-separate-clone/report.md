# 740 — Attended-сесія в окремому клоні блокується задачею runner-а в doing/ — звіт

## Що змінилось для власника
- **Сесію з вами в окремому клоні задача runner-а більше не зупиняє.** `board.py start --attended` і
  `next --attended` дивляться лише на задачі «з присутнім власником» у `doing/`. Задача runner-а, що лежить там, вашій
  не заважає і вам не пропонується. Обхід «з `todo/` одразу в `done/`», яким ішла сесія 2026-10-06, більше не потрібен.
- **Дві задачі «з присутнім власником» разом не стартують:** другій task board відмовляє і називає першу, а не задачу
  runner-а.
- **Runner, як і раніше, бачить лише свою задачу.** Звичайну задачу, яку стартують із `--attended`, коли в `doing/`
  вже лежить задача runner-а, task board не пускає: інакше runner побачив би в `doing/` дві свої.
- **README узгоджено:** `tasks/README.md` і `templates/project/tasks/README.md` («Задачі з присутнім власником»,
  крок 1) кажуть, що в окремому клоні чекати зупинки runner-а не треба.
- **Задача чекала вас не через код.** Перший audit не знайшов жодної невдалої перевірки, але PASS не приймався, поки
  була відкрита gate escalation задачі 902. Ви її закрили й відповіли «закрито»; новий overseer перевірив роботу
  наново — PASS (request `20261012T223205Z-8f667f`). Код у цій сесії не змінювався.
- **Поправка до моєї попередньої примітки в задачі:** нових перевірок у `tests/test_board.py` вісім, а не дев'ять.
  Числа `PASS 312 FAIL 6` і `PASS 318 FAIL 0` там правильні.

## Рішення, які я ухвалив сам
- **Бік задачі в `start` визначає сама задача** (рядок `Потрібна присутність власника: так`), а не прапорець
  `--attended`: інакше звичайна задача з прапорцем стала б поруч із задачею runner-а.
- **`next --attended` більше не друкує звичайну задачу, що лежить у `doing/`** — її показує `next` без прапорця.
  Overseer назвав це найсильнішим запереченням (поведінку прибрано) і перевірив: жоден наявний тест на неї не спирався,
  а `own()` для сесії з вами й далі знаходить звичайну задачу, коли задачі «з присутнім власником» немає. Якщо ви
  звикли питати `next --attended`, маючи в роботі звичайну задачу в тому самому клоні, — скажіть, поверну.
- **Unit заявив руками, а не через Stop hook:** код після першого request не мінявся, тож hook audit-у не попросив би.
  Turn file `.engine/artifacts/overseer/turn-2026-10-12-board-740-close.md` і `overseer_verdict.py request` — шлях зі
  skill `overseer`, той самий, яким закрито 719, 725 і 730.
