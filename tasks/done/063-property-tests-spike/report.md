## Таблиця «сцена × плече × повтор»
Модель в усіх сесіях — `claude-opus-5-5`. Рахує скрипт: **C** (caught) — набір падає на хибній
реалізації і проходить на правильній; **F** (fails on both) — падає на обох; **M** (missed) —
проходить на обох; **ok** — контрольна сцена: набір проходить на правильній реалізації і invariant
не вигадано. Повтори — в порядку запису. Плече В рахується з одним і тим самим набором входів
бібліотеки (`--hypothesis-seed=0`), тому повторний підрахунок дає те саме.

| Сцена (правило) | А: contract без «Invariants», приклади | Б: з «Invariants», приклади | В: з «Invariants», Hypothesis |
|---|---|---|---|
| `roundtrip` — надрукована ціна читається назад | F F F F C C F F F F C C | F C C C F C C C C F C C C C C F C C F C F C C C | C C C C C C C C C C C C C C C C C C C M C C C C |
| `conserve` — частини в сумі дають рахунок | C C C | C C C | C C C |
| `idempotent` — нормалізувати двічі те саме, що раз | C C C | C C C | C C C |
| `bound` — залишок не від'ємний | M M M M M M | C C C C C C | C C C C C C |
| `none` — контрольна, invariant немає | ok ok ok | ok ok ok | ok ok ok |
| **Впіймано (caught)** | **10 із 24** | **30 із 36** | **35 із 36** |

Чому повторів не порівну. Перші 45 сесій (5 сцен × 3 плеча × 3) дали розбіжність на двох сценах:
`roundtrip` (А 0 із 3, Б 2 із 3, В 3 із 3) і `bound` (А 0 із 3, Б і В 3 із 3). На них я додав по три
повтори на плече; `bound` зупинився на 0, 6 і 6 із 6. На `roundtrip` Б і В далі розходилися в межах
одного-двох прогонів, тому я додав ще шість на плече, а потім ще по дванадцять для Б і В — доки
різницю стало можна назвати (6 із 24 проти 0 із 24). `conserve` і `idempotent` не розходилися —
там по три. Жодного прогону не відкинуто; сесій з помилкою не було; жоден агент не змінив модуля.

Що ще записано в плечі В (39 сесій), читав я сам рядки генераторів, які скрипт виписав у запис:
- **Область генератора збігається з полем «Область» contract — в усіх 36 сесіях із invariant.**
  Ніхто не звузив область (ціни — від 0 до 999 999 999 центів; люди — від 1 до 100; полиця і
  кількості — будь-які цілі; тексти — рівно названі символи з обов'язковою літерою чи цифрою).
- **Перевірок здоров'я бібліотеки не приглушено ніде** (0 із 39).
- **Тест бібліотеки сам знайшов пастку** (з набором входів gates): `roundtrip` 22 із 24, `conserve`
  3 із 3, `idempotent` **0 із 3**, `bound` 6 із 6. На п'яти інших наборах входів: `roundtrip` і
  `conserve` — щоразу; `idempotent` — 4 із 5; `bound` — 4 із 5 у п'яти сесіях і 2 із 5 в одній.
  У `idempotent` пастку (пробіл поруч із дефісом) випадкові тексти зачіпають рідко — її впіймав
  приклад поруч; чесна широка область («будь-які цілі» в `bound`) теж робить влучання справою
  випадку. Єдиний M у плечі В — генератор, що з набором входів gates не видав жодної ціни від
  мільйона (перевірено окремо: найбільша з сотні — 636 341.98), а на п'яти інших видав.

## Висновок
**Б ловить стільки ж, скільки В, і більше за А — будувати лише розділ «Invariants» і його
перевірки, без бібліотеки й широкого пошуку.**
1. **А проти Б — різницю можна назвати.** У `bound` 0 із 6 проти 6 із 6; за суворим підрахунком
   10 із 24 проти 30 із 36. Механізм видно в самих файлах: без розділу tester пише по одному
   прикладу на рядок «Errors» contract («скасувати 4, коли зарезервовано 3») і не чіпає стану
   «зарезервовано нуль»; з розділом він пише `test_I1_…` з кількома послідовностями з поля
   «Область», і нуль серед них є щоразу.
2. **Б проти В — на входах різниці немає.** Плече Б дійшло до пастки в кожній із 36 сесій, і
   тест із номером invariant був червоний на хибній реалізації в кожній із них.
3. **Єдине, чим В відрізняється від Б, — «падає на обох» у `roundtrip`: 0 із 24 проти 6 із 24.**
   Це різниця справжня (не один-два прогони), але вона не про пошук входів. Імовірне пояснення —
   обсяг: у В удвічі менше тестів-прикладів (24 проти 53 у цій сцені), тож менше і тестів на
   здогад. Це здогад, а не вимір: плечі Б і В відрізняються ще й абзацом запиту.
4. **Бібліотека без широкого пошуку ненадійна навіть там, де область записано точно:** з набором
   входів gates її тест не знайшов пастку в `idempotent` жодного разу з трьох. Тобто
   будувати її без широкого пошуку (відповідь 3 у 048) не можна, а разом із ним вона на цих сценах
   не дала нічого понад приклади.

**Питання до contract — знову головний вихід tester.** Двозначність із `012.50` назвали 59 із 60
сесій `roundtrip`, в усіх трьох плечах. Різниця лише в тому, чи писав tester на суворіше
прочитання ще й тест.

## Що вибірка дозволяє стверджувати, а що ні
**Вибірка мала:** 105 сесій, п'ять сцен, одна модель, один автор сцен.

Дозволяє:
- Груба різниця між А і Б є, і вона в тому, що правило з областю, записане окремим рядком,
  стає тестом на краї області. Це трималося в усіх шести парах сесій `bound`.
- Грубої різниці між Б і В на входах пасток немає: 36 із 36 проти 35 із 36.
- На контрольній сцені розділ «немає — причина» не породжує вигаданих invariants (9 із 9).
- Розділ не здорожчує tester.

Не дозволяє:
- **Сказати, що бібліотека ніде не корисна.** Пастки писав я, і всі вони такі, що уважна людина
  здатна назвати вхід наперед. Помилок, яких ніхто не здатен назвати наперед (а саме заради них
  існує property-based testing), тут немає за побудовою. Живі slices покажуть це краще, ніж
  новий spike; тому в 064 записано питання про бібліотеку для розбору після десяти slices.
- **Сказати, як поведеться справжній planner.** Розділи «Invariants» писав я, знаючи клас пастки
  (поле «Порушить» називає іншу помилку, не підсаджену, але правило й область — влучні). Чи напише
  planner такий самий влучний invariant і чи відрізнить critic слабкий — не міряно.
- **Узагальнити частку «падає на обох».** Усі 14 випадків — один двозначний рядок одного contract.
- **Тонкі різниці.** `conserve` і `idempotent` мають по три повтори на плече (усі впіймано); різницю
  в 10–20 % там не видно.
- **Розділити «розділ у contract» і «абзац у запиті tester».** Плече Б отримало обидва разом.

**Вада сцени, яку я помітив уже після прогонів і за правилом задачі не виправляв:** каркас
`roundtrip` містить рядок із шаблоном розбору ціни (правильним, не хибним) — його бачили всі три
плеча однаково. Він міг підказати «кілька груп по три цифри», і до пастки в цій сцені дійшли всі
60 сесій, плече А теж. Тому `roundtrip` майже нічого не каже про пошук входу; він каже про «падає
на обох». Порівняння плечей це не зміщує, але сцена слабша, ніж задумано. Запис — у
`tasks/ANOMALIES.md`.
