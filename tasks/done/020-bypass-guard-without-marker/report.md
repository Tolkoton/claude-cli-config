## Що змінилось для власника
- Ловля приглушувань тепер працює завжди. Якщо файла-маркера (`PROJECT_MARKER`) у проєкті ще немає, ворота наприкінці ходу, як і раніше, не запускають лінтер, перевірку типів і тести, але доданий `# noqa`, `# type: ignore`, пропущений тест чи правку налаштувань лінтера зупиняють.
- Раніше в такому проєкті це все проходило мовчки: перевірка маркера стояла перед ловлею і вимикала її разом з рештою.
- Виправдане приглушування (`# gate-allow: причина`) проходить, як і з маркером. Чиста зміна без маркера не блокується.
- Зміна — у `.claude/hooks/gate.py` (функція `layer_checks`): ловля переставлена перед перевіркою маркера. Інші шари (`pre_commit`, `ci`) маркера не читали й не читають.
- Золотий набір має новий сценарій `vs-bypass-without-marker` і новий еталон `evals/baseline/claw/results-task-020.json` (119 сценаріїв).

## Демонстрація на хвилину
Тимчасовий репозиторій: маркер `pyproject.toml` названо, файла немає; у зміні — доданий `# noqa`. Вивід дослівний:

```
$ python3 .claude/hooks/gate.py --layer stop
gate[stop] 2 finding(s), exit 2
  block mod.py:1 [bypass/noqa] the diff adds a noqa — the gate is passed by silencing it, not by fixing the code
  log   - [marker] pyproject.toml not found — lint, types and tests skipped
exit: 2
```

Та сама тека, чиста зміна (`x = 2`), а `LINT_CMD` навмисно завжди падає: вихід 0, єдиний запис — `marker … lint, types and tests skipped`. Тобто лінтер без маркера не запускався.

Повторити самому:
```bash
python3 tests/test_gate.py | grep -i "marker"
python3 evals/run_hook_scenarios.py --engine-ref HEAD --only vs-bypass-without-marker
```

## Відкладене
- **Назвати в ході неіснуючий маркер — досі спосіб вимкнути лінтер, типи й тести.** `PROJECT_MARKER` не входить до переліку налаштувань воріт, зміну яких ловля зупиняє (`LINT_CMD`, `TEST_CMD` тощо). Те саме з `CODE_EXTENSIONS`: якщо прибрати звідти `py`, хід зі зміною лише `.py`-файлів до ловлі не доходить. Після цієї задачі приглушування в коді так уже не сховати (якщо змінено й `project.env`, ловля запускається), але самі перевірки — можна. Це окрема зміна поведінки для всіх проєктів, тому не робив; кандидат у нову задачу: додати обидва ключі до переліку.
- Черга уроків просить розбору (39 кандидатів, понад 30) — це окремий протокол, цієї задачі не стосується.

- **«Золотий набір» — це сценарії hook-ів** (`run_hook_scenarios.py`), як у попередніх задачах. Набір випадків `evals/scenarios/gate/cases.json` не чіпав: його еталон записано на іншій машині зі справжніми ruff і mypy, і тест вимагає, щоб еталон покривав усі випадки.
