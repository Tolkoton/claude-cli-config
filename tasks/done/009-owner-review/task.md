# 009 — Огляд для власника: що планували, що зроблено, що чекає (лише читання)

Залежить від: —
Аудит потрібен: ні

## Рішення власника
Огляд власник проводить тоді, коли має час, а не тоді, коли закінчилася задача. Огляд нічого не змінює в коді. Він збирає картину, а з розбору народжуються відповіді й нові задачі у скриньку.

## Що зробити
1. Команда python3 .claude/unattended/board.py review — лише читання.
   - Стан береться з гілки unattended/work в origin через git, а не з робочого дерева виконавця. Тож огляд можна запускати будь-коли, паралельно з роботою, з будь-якого клону.
   - Аргумент --since <commit або дата>; без нього — від найновішої мітки версії. Наприкінці документ друкує команду для наступного огляду.
   - Виводить один markdown-документ із розділами:
     - «Стан зараз»: задача у виконавця, скільки триває, витрати, чи чекає ліміту, чи зупинився і чому. Береться з файлів стану .claude/state/board/, якщо вони доступні; інакше — з git.
     - «Зроблено»: для кожної задачі з done/ — розділ «Що змінилось для власника», демонстрація, «Рішення, які я ухвалив сам», витрати, commit-и.
     - «Чекає на власника»: усі незаповнені «Відповідь:» з blocked/ (з контекстом і варіантами), пропозиції налаштувань, що чекають «так», відкриті ескалації, пропозиції правил.
     - «План»: todo/ у порядку виконання, із залежностями; що стоїть через залежність.
     - «Кандидати в нові задачі»: розділи «Відкладене» і «Чого мені бракувало» зі звітів готових задач; знахідки спрощувача для розбору, коли вони з'являться.
     - «Здоров'я»: останній повний прогін тестів і золотого набору, рядки постійного контексту з 200, витрати за період.
2. Команда Claude Code /review для сесії огляду з власником:
   - запускає огляд і проходить його з власником розділ за розділом;
   - записує відповіді на питання й нові задачі файлами за шаблоном задачі у скриньку (шлях — змінна BOARD_INBOX, за замовчуванням ~/engine-ops/tasks-inbox);
   - нічого іншого не змінює.
3. В tasks/README.md — інструкція для оператора: на прохання власника запустити огляд і надіслати документ.
4. Детерміновані тести на синтетичному репозиторії:
   - огляд не змінює жодного файла;
   - --since показує лише нове;
   - знайдено всі незаповнені відповіді;
   - огляд працює, поки виконавець посеред задачі.

## Готово, коли
