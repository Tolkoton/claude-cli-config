# Звіт: 739 — журнали без конфліктів злиття

## Що змінилось для власника
- **`merge=union` не додано, і він не потрібен.** Перевірка показала, що на журналах двигуна union тихо губить рядки
  записів і повертає розібраного кандидата в чергу lessons (відтворити: `bash .engine/artifacts/739-union/probe.sh`).
  `.gitattributes` не змінено.
- **Натомість зроблено за вашою відповіддю 1:** кожна сесія пише свої записи чотирьох журналів в окремий файл зі своїм
  ID сесії, тож гілки зливаються без конфлікту.

  | Журнал | Спільний файл (історія і те, що складено) | Файл сесії |
  |---|---|---|
  | ledger overseer-а | `.engine/overseer/ledger.md` | `.engine/journal/ledger/<сесія>.md` |
  | журнал аномалій | `tasks/ANOMALIES.md` | `.engine/journal/anomalies/<сесія>.md` |
  | parked | `.engine/overseer/parked.md` | `.engine/journal/parked/<сесія>.md` |
  | черга lessons | `.engine/lesson-queue.md` | `.engine/journal/lessons/<сесія>.md` |

- **Читати журнал тепер треба цілим:** `python3 .claude/hooks/journal.py show ledger|parked|anomalies|lessons`
  (чергу — `python3 .claude/hooks/lesson_queue.py list`). Спільний файл сам може ще не містити найновіших записів.
  Усі читачі двигуна (лічильник PASS поспіль, огляд, черга, перевірки дублів на task board) уже читають так.
- **`python3 .claude/hooks/journal.py fold`** складає записи всіх файлів сесій у спільний файл за часом, без втрат, і
  прибирає файли сесій, старші за 7 днів. Він потрібен лише для зручності читання очима; автоматично ніде не
  запускається. Робити його варто там, де гілки сходяться (після злиття в `main`), і не на двох гілках одночасно.
- **Черга lessons:** розібраний кандидат більше не видаляється — розбір стає ще одним рядком `resolved:<куди>`.
  Якщо дві сесії розібрали одного кандидата по-різному, скрипт не вибирає: `lesson_queue.py collect` кладе задачу в
  `tasks/todo/`, а агент вирішує командою `lesson_queue.py settle <id> --keep <куди> --why "…"`.
- **Три знахідки третього BLOCK виправлено** (ваша відповідь 2):
  - (а) шість сценаріїв golden set стежать за файлом сесії (`CLAUDE_CODE_SESSION_ID=golden`,
    `.engine/journal/<журнал>/golden.md`); новий тест не дає сценарієві знову стежити за спільним файлом журналу;
  - (б) той самий кандидат уроку, доданий на двох гілках у різні дні, стоїть у черзі один раз, з датою першої появи;
  - (в) покажчики в `.claude/references/hooks.md` і `docs/ARCHITECTURE.md` ведуть до файла сесії і `journal.py show`.
- **Overseer: PASS** (запит `20261011T080431Z-d38a0a`), з одним браком тесту — він уже лежить у `tasks/todo/778-…`.
- **Задача 104** (union для реєстрів) більше не чекає на 739. Для неї лишається застереження з перевірки: union може
  повернути рядок, який інша гілка видалила.
