# Звіт: 754 — що вважати «PASS бачив цей commit» у `mode.py check-close`

## Що змінилось для власника
- **Зроблено за вашою відповіддю (б).** Commit задачі з робочим кодом тепер покрито ще й тоді, коли його код пізніше
  в тій самій задачі замінив commit, який сам має PASS overseer-а. Типовий випадок: на commit був BLOCK, далі
  виправлення з PASS — раніше runner паркував таку задачу з причиною `minimum` назавжди, тепер вона закривається.
- **Суворість лишилась:** якщо commit-виправлення сам без PASS (або його змінили після PASS), непокритими названо
  обидва commit-и, від старішого до новішого.
- **Пізніший PASS, як і раніше, покриває раніший commit без audit-у,** якщо запит уже мав цей commit у HEAD — це
  ви лишили без змін, і тест на це стоїть, як стояв. Тому тест із початкового тексту задачі («check-close називає
  commit юніта 1») не дописано: він суперечив би вашій відповіді.
- **Overseer: PASS** (запит `20261011T083503Z-861bd3`), з двома браками тесту — вони вже лежать у
  `tasks/todo/779-…` і `tasks/todo/784-…`.
- Правило описано в `tasks/README.md` («Мінімум режиму при закритті»), у шаблоні проєкту і в
  `.claude/unattended/README.md`.

## Рішення, які я ухвалив сам
- **Відповідь (б) застосовано до кожного файла окремо.** Буквально (б) каже: «кожен файл commit-у пізніше змінив
  покритий commit». Але виправлення зазвичай зачіпає не всі файли commit-у з BLOCK. Тому правило таке: для кожного
  файла commit-у — або його пізніше змінив покритий commit задачі, або саме цей вміст бачив PASS. Це ширше за
  буквальне (б) рівно на випадок «виправлено один файл із двох», і в кінцевому стані однаково лишається лише код,
