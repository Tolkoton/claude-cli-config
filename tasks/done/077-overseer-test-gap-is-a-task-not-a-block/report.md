# 077 — Брак тесту, знайдений overseer-ом, — окрема задача, а не BLOCK — звіт

## Що змінилось для власника
- **Брак тесту більше не зупиняє роботу.** Може бути так: код робить те, що заявлено, тести зелені, умови
  «Готово, коли» виконано, а overseer бачить, що якогось тесту бракує або він слабкий (варіант коду з
  помилкою, який тести пропускають, або неперевірений крайній випадок). Тоді overseer відповідає **PASS** і
  перелічує такі місця в новому полі `test_gaps`. Скрипт `overseer_verdict.py` (не модель) кладе на кожне
  відкритий пункт у `tasks/todo/` з назвою перевірки, яку треба дописати: «Брак тесту (overseer): …».
  Той самий брак, знайдений удруге, не створює другого пункту.
- **BLOCK лишився для справжніх вад:** заява неправдива (тести червоні, поведінка зламана, умова «Готово,
  коли» не виконана), зміна щось ламає, а в перевірці #4 — лише приглушена перевірка (`gate-allow` і
  подібні). Якщо «Готово, коли» прямо вимагає саме цей тест, його брак означає неправдиву заяву (#1).
- **Три BLOCK поспіль і далі паркують задачу**, але PASS із браком тесту до них не рахується: три такі
  PASS поспіль нічого не паркують.
- **Захист від старої звички:** якщо overseer усе ж дасть BLOCK #4 за брак тесту, скрипт поверне йому
  відповідь з поясненням «відповідай PASS із `test_gaps`». Повторна відповідь не за схемою — INVALID, і
  audit повторить інший overseer, як і раніше для будь-якої відповіді не за схемою.
- **Ledger** показує брак тесту рядком `- Test gaps: …` разом із шляхом до пункту на task board.
- **testing.py** і далі бачить сигнал «тести слабкі» для наступного slice (обов'язкові випадки O4 і O7):
  PASS із браком тесту рахується так само, як колись BLOCK #4.

## Рішення, які я ухвалив сам
- **Межа «брак тесту / вада»:** брак тесту — лише коли код правильний, тести зелені й умови виконано. Якщо
  умова «Готово, коли» чи контракт вимагає саме цей тест, або пропущений випадок справді ламає код — це #1.
- **BLOCK #4 лишився для приглушених перевірок** (`gate-allow`, type-ignore, noqa, skip, послаблене налаштування).
  Це не брак тесту, а обхід перевірки. Скрипт розрізняє їх за словами в `reason`, а визначення дає точне
  формулювання «masked gap — gate-allow at …».
- **Відповідь повертається overseer-у, скрипт її не переписує.** Агент сам вирішує ще раз, чи там справді
  лише брак тесту, чи вада (#1). Переписати BLOCK на PASS мовчки означало б, що скрипт судить замість агента.
- **`test_gaps` дозволено й поруч із BLOCK** за іншу ваду: брак тесту записується, навіть коли юніт повертають
  з іншої причини.
- **Ключ пункту — назва перевірки:** той самий брак не плодить пунктів. Інший опис тієї самої перевірки
  створить новий пункт, бо порівнювати описи за змістом не можна без моделі.
- **Без task board** (сцени evals, проєкт без `tasks/`) брак записується лише в ledger.
- **testing.py** рахує брак тесту як колишній BLOCK #4. Ключ `overseer_blocks_check_4` не перейменовано:
  його читає менеджер тестування, і перейменування зачепило б записи.
