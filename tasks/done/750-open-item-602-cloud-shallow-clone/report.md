## Рішення, які я ухвалив сам
- **Рядок, коли fetch не вдався.** Ви сказали: «жодних попереджень і жодних питань до мене через брак історії». Рядок
  виводиться лише тоді, коли сам fetch не вдався (мережа, доступ), а не через брак історії. Він адресований агентові
  («запусти ту саму команду ще раз»), а не вам, і нічого не зупиняє. Без нього Stop gate потім блокував би turn
  незрозумілою помилкою двох suites, і причину довелося б шукати. Прибрати рядок — одна правка, якщо скажете.
- **Лише shallow clone.** Повний clone (без `--depth`) уже має всю історію і теги, які git отримує під час clone, тож
  його hook не чіпає й зайвого мережевого виклику на кожному старті сесії не робить.
- **50 секунд на fetch.** Двигун дотягується приблизно за секунду. Для дуже великого репозиторію fetch може не вкластися;
  тоді наступна сесія спробує знову.
