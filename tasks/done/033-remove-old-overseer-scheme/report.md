# 033 — Прибрати стару схему наглядача: звіт

## Що змінилось для власника
- **Стару схему прибрано.** Сесія більше ніколи не аудитує саму себе. У `overseer_stop.py` лишився один шлях: заява про готовий юніт → запит → окремий агент `overseer` → вердикт, записаний скриптом.
- **Спершу довелося зробити перенесення (пункт 3 задачі).** Перевірка показала: новий проєкт і проєкт без власних правок налаштувань отримували нову схему, а проєкт із власними правками `.claude/settings.json` — ні. Його файл лишався як був, без двох обробників, і звіт не казав, що додати.
- **Тепер `engine.py update` (і `install` поверх наявної копії) сам додає два обробники у файл налаштувань, який проєкт правив.** Усе інше у файлі лишається як було. У звіті оновлення є рядок `wire` з точним переліком доданого: подія, matcher, команда.
- **Якщо файл налаштувань не читається як JSON, його не чіпають.** Звіт каже чому, що без обробників жоден юніт не перевіряється, і містить готовий до вставлення JSON.
- **Проєкт, де обробників усе ж немає, не лишається мовчки без аудиту.** На заяву про готовий юніт hook відповідає `OVERSEER NOT WIRED`: агентові — не аудитувати самому, відкласти юніт; людині — українською, що запустити `engine.py update`.
- **Набуде чинності в проєктах після `engine.py update` на версію з цими змінами.** Hook і налаштування приходять одним оновленням.

## Рішення, які я ухвалив сам
1. **`engine.py update` дописує обробники у файл налаштувань, який проєкт правив, а не лише радить.** Задача каже «update додає налаштування нової схеми»; лише порада не дала б гарантії, якої ви вимагали. Це єдиний виняток із правила «правлений файл не чіпаємо», він записаний у `engine.py` і `.claude/ownership.txt`. Файл після цього переписується як JSON з відступом 2 — власне форматування проєкту може змінитися. Скасувати: один виклик `plan_wiring` у `engine.py`.
2. **Обробники, які вже є в `settings.local.json`, удруге в `settings.json` не додаються** — інакше вони спрацьовували б двічі. Наслідок: на іншій машині без цього локального файлу проєкт буде без обробників і отримає `OVERSEER NOT WIRED`.
3. **Відповідь `OVERSEER NOT WIRED` замість мовчання.** Без неї проєкт без обробників отримував би запит, який ніхто не може записати. Юніт у такому проєкті відкладається до людини.
4. **11 ситуацій зі старих сценаріїв лишив під єдиною схемою**, а не просто видалив усі 23: інакше золотий набір перестав би перевіряти умови спрацювання hook-а й автономний прогін.
5. **Два файли сценаріїв hook-а злито в один** (`50-overseer-stop.json`); результати ключуються за ідентифікатором сценарію, тож порівняння з еталонами це не зачіпає.
6. **`test_settings_wiring` не додав до швидкого набору** (3,6 с, справжнє встановлення старої версії); він іде в повному наборі.
