# 021 — Одна задача не зупиняє дошку; журнал аномалій: звіт

## Що змінилось для власника
- **Застрягла задача більше не зупиняє виконавця.** Три спроби поспіль без commit-а, понад 12 годин у роботі або вичерпаний бюджет задачі (`BOARD_MAX_USD`) — виконавець сам переносить задачу в `tasks/blocked/`, дописує розділ `## Чому зупинилась` (час і причина) та питання до вас із порожнім `Відповідь:`, і бере наступну задачу. Раніше він у цих трьох випадках зупинявся з кодом 1 (`stalled`, `deadline`).
- **Будь-яка ваша відповідь повертає задачу в чергу** з новим відліком часу і спроб, у свіжій розмові. Після зупинки через бюджет відповідь дає задачі ще один такий самий бюджет — це написано в самому питанні.
- **Незакомічена робота агента не губиться і не заважає наступній задачі:** виконавець ховає її в git stash, а команда `git stash apply <номер>` стоїть у розділі «Чому зупинилась».
- **З'явився журнал аномалій `tasks/ANOMALIES.md`:** час (UTC), задача, що сталося, що зроблено. Пише його виконавець, комітить разом із `tasks/`. Туди ж потрапляє те, що раніше було лише в локальному журналі подій або зупиняло дошку: push не вдався; задача зникла з дошки; агент повернув задачу в `todo/`, не закінчивши (таку задачу теж переносить у `blocked/`).
- **Огляд (`board.py review`, `/review`) має новий розділ «Аномалії»** — між «Чекає на власника» і «План». Він показує лише нові записи за період і каже, скільки їх у журналі всього.
- **Усю дошку зупиняє лише критичне** (стан `error`, код 1): конфлікт при pull (`reason=pull-conflict`); claude розлогінився (`reason=logged-out`, задача лишається в `doing/`, наступний запуск її продовжує, спроба не рахується); помилка git чи самої дошки, після якої комітити неможливо; ваш прапорець м'якої зупинки (код 0). Про зупинку через pull і вихід із claude виконавець теж робить запис у журналі.
- **Увага: виконавець, який працює зараз, запущений зі старим кодом.** Нова поведінка почне діяти з його наступного запуску.
- **Розпізнавання «claude розлогінився» не перевірене наживо** — лише на підробленому claude. Воно спирається на текст повідомлення («Please run /login», «Invalid API key», «Not logged in», прострочений токен). Якщо справжнє повідомлення звучить інакше, кожна задача з `todo/` по черзі піде в `blocked/` після трьох порожніх спроб — без витрат, але з шумом у журналі. Це записано в `docs/engine-limits.md`.

## Відкладене
- **Сховок git живе лише на сервері виконавця** — його не надсилають в origin. Якщо клон зникне, незакомічена робота застряглої задачі зникне з ним. Надійніший варіант — окрема гілка на кожну застряглу задачу; це окрема задача, якщо потрібно.
- **Журнал пише лише виконавець.** Те, що вважають дивним hook-и, ворота чи агент, іде у власні записи (ескалації, відкладене), не в `tasks/ANOMALIES.md`.
- **Решта зупинок із `state=error` лишилась, як була:** не та гілка, `board.py` відмовив (наприклад, дві задачі в `doing/`), не вдалося прочитати теку вхідних. Там виконавець справді не може рухатись; запису в журналі для них немає.
- **`--retry`** лишився, але майже не потрібен: застрягла задача вже не лежить у `doing/`, шлях назад — ваша відповідь.
- **`supervisor.sh`** (робота від DAG) не змінювався.

## Рішення, які я ухвалив сам
- **Відповідь після зупинки через бюджет дає ще один такий самий бюджет.** Інакше задача одразу застрягла б знову, скільки б ви не відповідали. Витрачене раніше лишається в рахунку задачі. Якщо ви хотіли, щоб бюджет піднімав лише оператор через `BOARD_MAX_USD`, — це треба змінити.
- **Незакомічену роботу — в git stash, а не лишати в дереві.** Інакше наступна задача почала б на чужих змінах і могла б їх закомітити як свої. Stash забирає і нові файли, які не належали агентові (ігноровані — ні).
- **Агент повернув задачу в `todo/`** — це теж «застрягла»: у `blocked/` з причиною. Раніше дошка зупинялась; якби просто пішла далі, взяла б ту саму задачу знову, без кінця.
- **Задача зникла зовсім** — запис у журнал, наступна задача. Раніше це зупиняло дошку.
- **Невдалий push — запис у журнал при кожній невдачі**, робота триває, як і раніше.
- **Вихід із claude розпізнається за текстом** короткої відповіді з помилкою і не рахується спробою; задача лишається в `doing/`, бо не вона винна.
- **Про критичну зупинку теж є запис у журналі** (pull, вихід із claude), і його надіслано в origin, коли це можливо, — щоб ви бачили причину в огляді, не заходячи на сервер.
- **«Нові записи» в огляді після `--since <commit>`** — це ті, яких у журналі на той commit ще не було; після дати — за часом запису.
- **Розділ «Чому зупинилась» один:** кожна наступна зупинка додає в нього рядок, а в питання — наступний номер; попередні відповіді лишаються.
- **Стани `stalled` і `deadline` виконавець більше не пише;** огляд їх ще розуміє — для старих файлів стану.
