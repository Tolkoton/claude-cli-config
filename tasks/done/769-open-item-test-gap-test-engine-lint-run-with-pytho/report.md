## Відкладене
- **Форма, новіша за 3.11, поза `.claude/`** проходить lint на машині без `python3.11`, і одна така вже є:

  який не зміг запуститись, не пройшов.

## Рішення, які я ухвалив сам
- **Тест тримає вердикт усього lint-у, а не рядок перевірки компіляції.** Задача просила «FAIL перевірки найстарішого
  Python або дістатись 3.11 через `uv`/`uvx`». Lint робить третє: перевірка компіляції й далі друкує `note`, а червоним
  його робить `ruff --target-version`. Тест вимагає лише ненульовий exit, рядок `FAIL: engine lint has findings` і
  згадку `testing.py` у знахідці — будь-який із трьох шляхів його задовольнить.
- **Окремий набір, а не нові рядки в `test_engine_lint.py`:** перевірка запускає сам цей файл на копії, тож усередині
  нього вона викликала б себе.
- **PATH сцени — дзеркало всього PATH машини без `python3.11`**, а не короткий перелік інструментів. Перша спроба з
  переліком (`python3`, `uv`, `uvx`, `ruff`, `mypy`) зламала mypy: його запускач із кешу `uv` потребує `realpath` і
  `dirname`.
- **У копію повернуто саме той один рядок, що стояв до задачі 748** (замість двох теперішніх). Перша спроба міняла лише
  другий рядок, lint червонів через невикористану змінну (`F841`), і перевірка exit-коду нічого не розрізняла.
- **Оточення для запуску — через `tests/hook_env.py`.** Перший прогін швидкого набору був червоний:
  `tests/test_hook_env.py` не приймає новий набір, який називає hook і не бере оточення з `hook_env()`. Виправлено в
  тесті, не винятком у `tests/hook-env-exempt.txt`.
- **Набір у швидкому наборі, хоч і 4,5 с** (поріг там «близько 2 с»): сам lint стоїть на Stop gate, тож зміна, яка
  прибирає `--target-version`, має зупинятись там само.
- **Кандидата в уроки `7ed66d3c` відкинуто:** це test gap задачі 768, він уже є задачею
  `tasks/todo/1745-open-item-test-gap-an-interpreter-independent-bug.md`, тривалого уроку в ньому немає.
