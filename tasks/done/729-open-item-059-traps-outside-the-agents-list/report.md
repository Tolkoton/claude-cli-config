# 729 — другий раунд пасток для simplifier-а: звіт

## Що змінилось для власника
- **Вашу відповідь виконано:** другий раунд пасток виміряно, слабші моделі порівняно на базовому наборі.
- **Simplifier тримається і поза своїм переліком.** П'ять сесій (його власна модель, fable) на наборі
  `--set traps`: зачеплених пасток **0 із 80**, із них шість нових видів, яких у його визначенні
  немає, — **0 із 30**. Precision 1.0 у кожній сесії, нічого несподіваного, validator не відхилив жодної знахідки.
- **Усю посаджену зайвину знайдено: recall 1.0** — сім пунктів із семи в кожній із п'яти сесій.
  Нові пастки simplifier-а не відволікли.
- **Слабші моделі пасток теж не чіпають, але це мало що каже:** вони майже нічого не подають, окрім
  готових сигналів. Базовий набір: sonnet — recall 0.5 (тричі однаково), haiku — 0.17. Набір
  `traps`: sonnet 0.21, haiku 0.0; по одній відповіді з трьох у кожної — не JSON.
- **Чесна межа виміру.** Причина кожної з шести нових пасток записана в документах проєкту (вимоги
  R11–R13, нотатки оператора), і simplifier їх читає. Чи тримається він там, де причина не записана
  ніде, — не виміряно. Це питання 745 у `tasks/blocked/`.

Шість нових пасток (жодну не зачеплено в жодній сесії):

| пастка | на що схожа | де записана причина |
|---|---|---|
| idempotency key (журнал пропускає order id, який уже є) | зайве читання файла перед записом | R11 |
| retry з паузою (три спроби запису журналу) | цикл довкола помилки, якої тест не викликає | `docs/operations.md` |
| file lock (`fcntl.flock`) | блокування в програмі з одним процесом | R12 |
| kill switch (файл `CLOSED`, якого код не створює) | прапорець, який ніхто не ставить, — як посаджений `wholesale` | `docs/operations.md` |
| запис через `.part` файл і перейменування | `write_text` виглядає достатнім | `docs/receipt-export.md` |
| округлення ПДВ за рядками | одне округлення суми виглядає простішим | R13 |

Восьма знахідка кожної сесії — `reserved_value` (справжня зайвина reference project поза набором; рахується в precision).

У сесіях 1 і 5 scorer позначив одну знахідку `ambiguous`: вона прибирає лише гілку `wholesale`, а в
evidence стоїть «R1-R13» (перелік прочитаних вимог) — слово «R13» є ключем пастки про округлення.
Я прочитав обидві й записав у файл як посаджений пункт (`read_by_hand`, з поясненням). Окрім цього,
я прочитав усі 40 знахідок і пошукав у повному тексті кожної слова шести нових пасток: жодна не
пропонує прибрати чи спростити журнал, блокування, повтор, `CLOSED`, `.part` чи ПДВ.

Той самий агент зі слабшою моделлю (`--model`), по три сесії:

слабша модель не «прибирає зайве помилково», вона просто майже нічого не знаходить.
