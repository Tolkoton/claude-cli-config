# 072 — Захист від видалення коду без тесту: звіт

## Що змінилось для власника
- **Ворота тепер блокують видалення коду, якого не торкався жоден тест.** Наприкінці ходу і перед
  commit-ом: зникла функція, клас чи файл робочого коду, або всередині однієї функції прибрано
  понад 20 рядків — і тесту на цей код не було — хід не закінчується. Це блок, не попередження.
- **Перенесення — не видалення.** Якщо функція чи клас із тим самим іменем з'явилися будь-де в тій
  самій зміні (зокрема в новому файлі), або прибрані рядки додано знову деінде — ворота мовчать.
- **«Чи був тест» — двома способами.** Якщо проєкт задав `COVERAGE_CMD` у `project.env` — точно:
  команда запускається на коді *до* зміни, і видно, чи виконувалися саме ці рядки. Без неї —
  грубіше: у модуля є свій файл тестів або ім'я згадано в тестах.
- **Три шляхи пройти блок:**
  1. тест, що фіксує нинішню поведінку (може лежати в тій самій зміні, ще не закомічений);
  2. мертвому коду тест не потрібен: знахідка спрощувача з доказом від інструмента, яку ви
     підтвердили у своєму терміналі — `python3 .claude/hooks/delete_guard.py confirm <файл знахідок> F-…`.
     У сесії агента команда відмовляє; знахідку без доказу від інструмента не приймає;
  3. ваш дозвіл у запечатаному контракті: `gate-allow: delete — <причина>` або
     `gate-allow: <шлях> — <причина>`.
- **Поріг — ключ `DELETE_GUARD_LINES` у `project.env`, початкове значення 20.** Змінити його агент
  не може: проходить лише зміна, названа в запечатаному контракті (як `PROJECT_MARKER`).
  `COVERAGE_CMD` захищено як інші команди воріт.
- **Чесні межі записано в `docs/engine-limits.md`** (розділ «The delete guard»): покриття не
  означає перевірку результату; без `COVERAGE_CMD` і для мов, крім Python, перевірка грубіша.
- Конституцію і `.claude/settings.json` не змінено. Проєкт без видалень нічого не помітить:
  перевірка додає близько 0,1 с до кінця ходу.

## Демонстрація на хвилину
```bash
python3 tests/test_delete_guard.py     # 56 перевірок, близько 12 с; сцени задачі названі в рядках «ok»
python3 .claude/hooks/delete_guard.py show    # поріг, спосіб перевірки, що підтверджено власником
```
Те саме руками, у будь-якому проєкті з двигуном: видаліть функцію з модуля без тестів і запустіть
`python3 .claude/hooks/gate.py --layer stop` — exit 2 і рядок
`DELETE GUARD legacy.py:4 [delete/untested] the change deletes code no test touched (function export_csv) …`
із трьома шляхами пройти.

Сцени з «Готово, коли» — усі в `tests/test_delete_guard.py`, блок показано першим:

| Сцена | Результат |
|---|---|
| видалено функцію без тесту | блок: кінець ходу, протокол hook-а, перед commit-ом; так само клас і файл |
| з тестом | проходить: файл тестів модуля; згадка імені; тест, написаний у тій самій зміні; тест, видалений разом із кодом |
| перенесено | проходить: у новий файл, перейменований файл, метод став функцією, 25 рядків винесено в іншу функцію |
| підтверджена знахідка спрощувача | проходить; підтвердження в сесії агента, знахідка без доказу від інструмента і «так», дописане агентом у журнал рішень, — блок |
| `DELETE_GUARD_LINES` змінено без дозволу | блок `bypass/config`, навіть із власною причиною поруч і з дозволом на весь файл; із запечатаним контрактом, що називає ключ, — проходить |
| понад поріг рядків у функції | 21 рядок — блок, 20 — проходить; власний поріг проєкту діє |
| `COVERAGE_CMD` | у модуля є файл тестів, але функцію ніхто не виконував — блок (груба перевірка пропустила б); команда справді бачить код до зміни |

Кожну нову перевірку я ще й ламав навмисно (тринадцять поломок: захист вимкнено; ніщо не
перенесення; рядки не повертаються; сесія може підтверджувати; доказ не потрібен; покриття завжди
«так»; покриття на новому коді; підтвердження діє на будь-який файл; поріг ігнорується; клас
рахується по методах; лише нові тести; лише старі тести; ключ порогу не захищено) — щоразу сцени
падали. Дві поломки спершу не ловилися — сцени дописав.

Живий прогін зі справжніми pytest і coverage.py (через `uvx`, у тимчасовому проєкті): функцію
без тесту в модулі, що *має* файл тестів, видалено — блок із поясненням «no test executed it on
the code before the change».

`bash tests/run_all.sh` (один повний прогін, на commit-і `4f86618`): 63 набори з 64 зелені. Червоним
був `tests/test_gate_allows.py` — одна його сцена копіює `gate.py` в окрему теку без сусідніх
скриптів, а ворота тепер не працюють без `delete_guard.py` (падають із блоком — сувора сторона).
Сцену виправлено (вона копіює і новий скрипт), набір перезапущено окремо: 77 із 77. Повний набір
удруге не запускав — правило дошки «один раз наприкінці»; змінено лише один рядок тесту.

## Відкладене
- **Калібрування порогу — окремою задачею, коли буде історія.** Пропоную таку: «Порахувати на
  історії commit-ів проєкту, скільки рядків усередині однієї функції прибирали зміни, які потім
  не довелося повертати, і скільки — ті, що повертали (revert, або рядки з'явилися знову);
  запропонувати власникові значення `DELETE_GUARD_LINES`, за якого блок ловить другі й не чіпає
  перші; застосовує власник». Рахувати є сенс, коли захист попрацює на справжньому проєкті після
  `/onboard` (073): у самому двигуні видалень без тесту майже немає.
- **Підтвердження знахідки з дошки.** Зараз підтвердити знахідку спрощувача можна лише командою у
  своєму терміналі на сервері. Щоб це робилося відповіддю «так» на дошці, потрібна нова дія в
  короткому переліку виконавця — це зміна виконавця, окрема задача.
- **Commit виконавця не запускає шар `pre_commit`.** `commit_checkpoint.sh` ворота не викликає,
  тож видалення, закомічене посеред ходу, наприкінці ходу вже не видно (так само, як для захисту
  від обходу; записано в межах). Закриває це git-hook `pre-commit` або виклик воріт у скрипті.
- **Скрипт «тест проходить на коді до зміни»** (з розділу 3 проєкту) будує задача 074; без
  `COVERAGE_CMD` захист вірить, що тест, який згадує ім'я, справді щось перевіряє.
- **Імена — лише для Python.** Для інших мов рахуються прибрані рядки у файлі; функція, коротша
  за поріг, зникає непомітно. Рядки поза функціями в Python не рахуються.
- Дві функції нового скрипта трохи перевищують обмеження складності двигуна (попередження, не блок).

## Рішення, які я ухвалив сам
- **Без `COVERAGE_CMD` досить одного з двох сигналів:** у модуля є файл тестів *або* ім'я згадано
  в тестах. Суворіший варіант (вимагати згадки імені) блокував би кожну приватну допоміжну
  функцію, яку тести викликають непрямо, і штовхав би агента дописувати ім'я в тест заради
  воріт. Ціна: у модулі з файлом тестів грубо проходить будь-яка функція. Головний випадок —
  модуль зовсім без тестів — ловиться. Точна відповідь — `COVERAGE_CMD`.
- **Тести «до» і «в зміні» рахуються разом.** Тест, видалений чи переписаний разом із кодом,
  усе одно означає «тест був»; тест, написаний заради видалення, рахується ще до commit-а. Із
  `COVERAGE_CMD` це два прогони: спершу тести як були; якщо цього мало — ще раз із тестами зміни.
- **Формат покриття — `coverage.json` від coverage.py** (`coverage json`), у робочій теці команди.
  Команда запускається в чистій копії старого commit-а (`git archive`), результат кешується.
  Якщо звіту немає — попередження і груба перевірка, а не блок: зламана команда покриття не має
  зупиняти всю роботу, а груба перевірка лишається.
- **Перейменування функції — це видалення старого імені** (якщо тесту на неї не було): проєкт
  визначає перенесення за іменем. Рядки, додані знову деінде, не рахуються видаленими.
- **«Доказ від інструмента» — це сигнал `simplify_signals.py`** (vulture тощо), а не читання чи
  судження агента. Підтвердження записується в стан машини (`.claude/state/delete-guard/`), бо
  журнал рішень спрощувача (`.engine/simplifier/decisions.jsonl`) агент може писати сам.
  Підтвердження покриває лише те, що назвала знахідка: символ, визначення на її рядках або файл.
- **`DELETE_GUARD_LINES` захищено суворо** (лише запечатаний контракт, що називає ключ), бо
  підняти поріг — означає вимкнути частину захисту; власної причини агента поруч не досить.
  `COVERAGE_CMD` — як інші команди воріт (причина поруч, її читає наглядач): інакше `/onboard`
  не зміг би її задати. Записати в `project.env` типове значення 20 — не зміна.
- **Для воріт «не задано» і «порожньо» тепер одне й те саме для всіх ключів** — інакше додати в
  `project.env` порожній `COVERAGE_CMD=""` було б «зміною налаштувань воріт».
- **Робочий код — файл із розширенням із `CODE_EXTENSIONS`, який не є тестом** (теки `tests/`,
  `test/`, `spec/`, `__tests__/`; імена `test_*`, `*_test`, `*.test`, `*.spec`, `conftest`).
  `SOURCE_DIRS` не використовую: у двигуні він містить `tests`, а ворота й раніше його не читали.
- **Рядки docstring, коментарі й порожні рядки у поріг не входять;** клас без методів вважається
  покритим, якщо виконувалося його тіло (інакше про нього нічого знати).
- **Один запис на файл:** усі видалення файла без тесту — одне зауваження з переліком.
- `tests/test_delete_guard.py` не у швидкому наборі воріт (12 с при бюджеті 20 с на весь набір).
- `AGENTS.md` не змінював: запас постійного контексту малий, захист описано в `gate.md` і `hooks.md`.
- Сигналу наглядачеві не подавав: аудит платний, а задача його не замовляла.
