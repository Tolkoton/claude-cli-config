# 104 — Файли-реєстри без конфліктів при злитті — звіт

## Що змінилось для власника
- **`tests/fast-suites.txt` більше не конфліктує при злитті.** У `.gitattributes` йому додано `merge=union`: коли дві
  гілки дописали різні рядки, git лишає обидва. Працює і для merge, і для rebase.
- **У перелік увійшов один файл.** Огляд інших кандидатів нижче: жоден не підходить, і для кожного названо чому.
- **Скільки це прибирає.** У повторі історії task board (той самий replay, що в задачі 083) було 256 конфліктів файлів
  у 40 файлах, із них 50 — `tests/fast-suites.txt`, найбільше з усіх. З `merge=union` лишається 206 у 39 файлах, у
  цьому файлі — жодного. «Половина» з проєкту 083 — це частка злиттів із конфліктом, у яких був цей файл; за файлами
  це п'ята частина.
- **`tests/run_all.sh` тепер запускає набір один раз, навіть якщо його рядок стоїть у переліку двічі.** Union може
  лишити дубль рядка; раніше такий набір запустився б двічі.
- **Ціна union, яку треба знати.** Union може повернути рядок, який інша гілка видалила.
  - Якщо набір видалено разом із файлом — `run_all.sh --fast` зупиняється з кодом 2 і називає набір. Це гучно:
    рядок треба видалити руками. Раніше на цьому місці був конфлікт, тож рука була потрібна так само.
  - Якщо набір лише винесли зі швидкого набору (файл лишився, бо він повільний) — рядок повернеться **мовчки**, і
    Stop gate знову запускатиме цей набір. Перевірки на це немає; є лише правило в
    `docs/working-on-the-engine.md`: після злиття, яке зачепило перелік, подивитися на нього.
- **У встановлені проєкти нічого не їде** — так само, як вирішила задача 739: `.gitattributes` і `tests/` належать
  лише цьому репозиторію (`project` у `.claude/ownership.txt`).

## Демонстрація на хвилину
```bash
python3 tests/test_registry_merge.py                           # PASS 18   FAIL 0
git check-attr merge -- tests/fast-suites.txt AGENTS.md        # union; unspecified
python3 .engine/artifacts/104-registry/conflicts.py            # 256 конфліктів у 40 файлах, близько двох хвилин
python3 .engine/artifacts/104-registry/conflicts.py --union    # 206 у 39 файлах; 110 злиттів переліку, дублів 0
```
Що перевіряє `tests/test_registry_merge.py` (справжні `.gitattributes` і `run_all.sh` на синтетичних репозиторіях):
- дві гілки дописують різні набори — merge і rebase без конфлікту, обидва рядки на місці, кожен набір запущено раз;
- дві гілки дописують той самий набір — він запускається раз, і тоді, коли union лишив рядок двічі;
- негативні випадки: файл поза переліком конфліктує, як і раніше; сам реєстр без атрибута конфліктує; рядок
  видаленого набору дає код 2 з назвою.
