# 725 — Інші платні скрипти вимірювань: сесія, яку API не пустив, — помилка, а не результат — звіт

## Що змінилось для власника
- **Файл результатів чотирьох runner-ів тепер сам каже, чи йому можна вірити.** `evals/run_analyst_evals.py`,
  `run_manager_evals.py`, `run_tester_evals.py`, `run_simplifier_evals.py` пишуть у файл `"status"`:
  `complete` (усі заплановані сесії відбулися й оцінені), `partial` (частина) або `no-results` (жодної). Сесія, яку API
  не пустив (`is_error`, 401), і раніше була рядком помилки без оцінки — вади «записано як прогін» у цих скриптах не було;
  виправлено те, що довкола.
- **Така сесія більше не псує числа.** Summary рахує її в `errors` і не бере в жоден знаменник: analyst і tester раніше
  писали «0 of 1», ніби сесія відбулась і провалилась.
- **`run_simplifier_evals.py` більше не завершується з кодом 0,** коли одна сесія відповіла, а іншу API не пустив, або
  коли прогін обрізала `--max-usd`: тепер код 1, якщо файл не `complete`.
- **`evals/compare_audits.py`:** сцена, яка є лише в одному файлі й не має там жодної чинної сесії, лишається
  «only after» / «only before» з кодом 0, але рядок `Result:` тепер називає її як не виміряну.
- **`evals/run_second_opinion_evals.py`** із задачі вже не існує (прибрано задачею 732).
- **Задача чекала вас не через код.** Другий audit не знайшов жодної невдалої перевірки, але PASS не приймався, поки була
  відкрита gate escalation задачі 902. Ви її закрили й відповіли «закрито»; новий overseer перевірив роботу наново —
  PASS (request `20261012T110326Z-e7fbef`). Код у цій сесії не змінювався.
- **Задача лежить у `blocked/`, а не в `done/`, і знову не через код.** `mode.py check-close` не приймає цей PASS:
  чотири файли задачі після її commit-а `6a0d334` змінили задачі 726, 728 і 730, а перевірка шукає PASS на вміст
  файлів саме з того commit-а. Питання 2 у задачі — як це закрити.
