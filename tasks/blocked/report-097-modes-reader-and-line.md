## Що збудовано (у patch-і)
- **Режим тепер пишеться в задачі.** Під назвою задачі можна поставити рядок `Режим: ескіз`, `Режим: соло` або `Режим: конвеєр`. Задача без рядка — `соло`, тобто все працює так, як працювало досі. Шаблон `tasks/TEMPLATE.md` тепер має рядок `Режим: соло` з підказкою в коментарі.
- **Один читач режиму — `python3 .claude/hooks/mode.py show`.** Він друкує один рядок: режим задачі, супровід, «без нагляду» і тип роботи, кожне з джерелом. Нічого не пише. Цей рядок runner дописує в перше повідомлення кожної сесії, а overseer отримує його в пакеті запиту (`request.json`, поле `mode`).
- **Агент піднімає режим сам, униз — лише ви.** `mode.py raise конвеєр --why "…"` дописує у файл задачі розділ `## Режим піднято` (коли, з якого на який, чому). Униз і на той самий режим скрипт відмовляє. Підняття діє лише до кінця цієї задачі: воно живе в самому файлі задачі, файла стану режиму немає. Скасувати підняття можете ви: видаліть цей розділ.
- **Недійсні поєднання відхиляє скрипт:** `hotfix.py start` — у режимі `ескіз` і `конвеєр`, `bugfix.py prove` — у режимі `ескіз`.
- **Рядок, що не називає режиму, task board не бере.** `Режим: абищо` (або два рядки `Режим:`) з inbox не забирається: файл лишається в inbox, а в журналі аномалій — один запис, чому. Таку задачу, якщо вона вже лежить у `todo/`, runner обходить, а `board.py summary` пише «не береться: … — чому».
- **Огляд показує режим кожної задачі:** у «Стан зараз» (задача в `doing/`), у «Зроблено» (з підняттям і його причиною), під кожним питанням у «Чекає на власника» і в «План».
- **«Без нагляду» тепер обчислює одне місце.** П'ять місць (`board.py`, `env-probe.sh`, `goals.py`, `hotfix.py`, `park-ask-gated.py`) раніше рахували це кожне по-своєму, тепер вони питають `mode.py`. Дві зміни на межі: hook `park-ask-gated.py` тепер бачить і змінну runner-а `CLAUDE_UNATTENDED_SESSION=1`, а не лише файл режиму; `env-probe.sh` визнає змінну лише зі значенням `1` (як решта). Runner ставить обидва, тож у його роботі нічого не змінилось.
- **Документи:** у `tasks/README.md` (і його копії для нових проєктів) — розділ «Режим задачі» і рядок у правилі 2 для агента; у `docs/OWNER-GUIDE.md` — розділ «Як обрати режим».
- Перевірки мінімуму при закритті і карантину ескізу тут ще немає: це задачі 098 і 099 (так і написано в README).

## Демонстрація на хвилину
```bash
python3 .claude/hooks/mode.py show                 # режим задачі в doing/ з джерелами
python3 tests/test_mode.py | tail -1               # PASS 65   FAIL 0 — негативні випадки першими
python3 tests/test_board_review.py | tail -1       # режим у кожному розділі огляду
```
Негативні випадки з критерію готовності (усі в `tests/test_mode.py`):
- `Режим: абищо` з inbox — `020-bad.md skipped: «Режим: абищо» — такого режиму немає: ескіз, соло, конвеєр — the board does not take it`;
- `mode.py raise соло` на задачі в конвеєрі — exit 2, `the task is in «конвеєр» already; a raise goes up only`, файл не змінено;
- `/hotfix` з `Режим: ескіз` — `hotfix.py start` exit 2, `a fix is never made in quarantine: /hotfix is refused in the mode «ескіз»`, картки немає.
Позитивний: задачу підняли соло → конвеєр і перенесли в `done/`; наступна задача без рядка — `mode.py show` каже `режим: соло (рядка «Режим:» немає → соло)`.
