# 739 — merge=union для журналів: що показала перевірка

`.gitattributes` не змінено. Платних прогонів не було.

## Коротко
Передумова задачі — «union залишить обидва набори рядків» — для журналів двигуна **хибна**. Git зливає за рядками. Однакові рядки двох паралельних записів (`- Хто записав: runner`, `- Auditor: overseer agent`, `- Class: human-input`) він залишає один раз, тож записи втрачають свої рядки, а тіло одного запису може «прилипнути» до заголовка іншого. У черзі lessons union повертає вже розібраного кандидата, якщо його рядок стояв поруч із новим. Конфлікт видно й розв'язують руками, а ці втрати тихі. Тому я не додав `merge=union` для жодного з п'яти файлів.

## Докази — `bash .engine/artifacts/739-union/probe.sh` (лише git)
- **ledger** (запис вставляється згори, `overseer_verdict.write_ledger`): після злиття `## … slice-b — PASS` стоїть одразу над `## … slice-a — PASS`, і в slice-b немає жодного рядка тіла (`- Verdict`, `- Check`, `- Auditor`).
- **ANOMALIES** (дописується в кінець, `board.anomaly`): у запису 003 зник рядок `- Хто записав: runner`.
- **черга lessons**: гілка a розібрала `#bbbb2222` (`lesson_queue.remove_line`), гілка b дописала `#cccc3333` одразу після нього. Після злиття `#bbbb2222` знову в черзі.
- `parked.md` у ручній перевірці поводиться так само, як ANOMALIES: у запису unit-b зник `- Unblocks when: …`. `escalations.md` має той самий формат — записи з кількох рядків.
- Хто пише і чи видаляє (код + історія git, commit-и з видаленими рядками / усього): `lesson-queue.md` — `lesson_queue.py` видаляє рядки при `resolve` (3/46); `ledger.md` — вставка згори і дописування в кінець (`simplifier.py`), 2/33 (ручні правки); `ANOMALIES.md` — лише дописування, 0/27; `escalations.md` — код не пише (пишуть агенти), 2/21; `parked.md` — лише дописування кодом, 6/12 (ручні позначки «закрито» в 2026-10-03…05).
- Висновок: критерій «лише дописують» потрібний, але не достатній. Навіть ANOMALIES, який йому відповідає, union псує через однакові рядки в записах.

## Варіанти
**А. Лишити, як є** — конфлікт у журналі розв'язувати за вашим правилом («рядки origin як є, потім свої, нічого не викидати»), руками, цілими записами. Нічого не будувати.

**Б. Невеликий скрипт-розв'язувач** (рекомендую, якщо конфліктів стане багато). `python3 .claude/unattended/merge_journal.py <файл>`: бере файл із маркерами конфлікту і складає обидві сторони **цілими записами** (`## …` до наступного `## …`), без злиття рядків. Для черги lessons — рядок за `#id`, а розібрані на іншій гілці не повертає (через `git show :1: :2: :3:`). Агент запускає його після конфлікту замість ручної правки. Тест — на синтетичному репозиторії, як у probe.

**В. Власний git merge driver** (`merge=journal` у `.gitattributes` + `merge.journal.driver` у `.git/config`). Автоматично, але визначення driver-а не версіонується: кожен клон і кожна хмарна сесія мусять його налаштувати, інакше git мовчки робить звичайне злиття. Не раджу.

**Г. Змінити формат журналів так, щоб кожен запис закінчувався унікальним рядком** — тоді union не склеює хвости. Зачіпає всіх записувачів і всі наявні записи. Не раджу.

## Ownership
`.gitattributes` належить лише цьому репозиторію (`project **` в `.claude/ownership.txt`) і у встановлені проєкти не їде. Нічого не змінено, бо `merge=union` не додано.
