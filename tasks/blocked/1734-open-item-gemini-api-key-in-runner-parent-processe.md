# 1734 — GEMINI_API_KEY лишилась у батьківських процесах runner-а (tmux server)

Залежить від: —
Аудит потрібен: ні
Відкритий пункт: gemini-api-key-in-runner-parent-processes

## Що сталося
Задачу 777 закрито: у середовищі сесії агента, яку стартує runner, змінної GEMINI_API_KEY немає (перевірено 2026-10-13, лише назви, значення не читалось). Але unset стоїть усередині команди, яку виконує tmux, тому процеси над runner-ом змінну мають: tmux server сесії engine-board (його команда — tmux new -d -s engine-board …), процес bash -c, що виконує цю команду, і глобальне середовище tmux (tmux show-environment -g показує назву GEMINI_API_KEY). Сам board-runner.sh і процес claude її вже не мають. Агент працює під тим самим користувачем Linux, тож може прочитати її з /proc/<pid>/environ батьківського процесу або командою tmux show-environment -g; hooks цього не зупиняють (мої перевірки назв цими шляхами пройшли). Тобто випадково (env, printenv, echo) агент ключа вже не бачить, а навмисно — бачить. Прибрати змінну з оболонки, з якої стартує tmux, може лише оператор.

## Питання до власника
1. Що робити зі змінною GEMINI_API_KEY у процесах над runner-ом? Варіанти: (а) оператор прибирає її ДО старту tmux — стартує командою env -u GEMINI_API_KEY tmux new -d -s engine-board … (або прибирає export із профілю оболонки) і перезапускає tmux server цілком (board-runner.sh --stop-after-task, далі tmux kill-server, далі новий старт), після чого агент перевіряє назви в /proc батьківських процесів і в tmux show-environment -g; (б) лишити як є: це відома межа «The same Linux user» з docs/engine-limits.md, від навмисного читання двигун не захищає, пункт закривається без змін; (в) окрема задача двигунові: hook відмовляє командам, що читають /proc/*/environ і tmux show-environment, — це зупинить лише наївне читання, не навмисний обхід. Раджу (а): це одна зміна в команді старту, і ключа не лишається в жодному процесі, до якого дістає агент; (в) без (а) ключа не ховає. Напишіть літеру.
   Відповідь: (б) — ключ однаково лежить у файлах OpenClaw, які той самий користувач Linux може прочитати, тож перезапуск tmux його не сховає; справжнє розділення — окремий користувач Linux для сесій агента, це на потім. Закрий пункт без змін.
