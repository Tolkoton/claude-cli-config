# 718 — Петля символьних посилань у шляху з командного рядка дає traceback у чотирьох скриптах

Залежить від: —
Аудит потрібен: ні
Відкритий пункт: 716-resolve-loop-other-scripts

## Що сталося
Знайдено під час пошуку «тих самих місць» у виправленні 004 (.engine/bugs/004-symlink-loop-traceback.md, розділ 4). До Python 3.12 Path.resolve() на петлі символьних посилань піднімає RuntimeError, а не OSError. Чотири місця зводять поданий шлях через resolve() без жодного try: .claude/hooks/bugfix.py:116 (test_files, аргумент --test; підтверджено: RuntimeError замість «is not a file of this project»), .claude/hooks/goals.py:350 (шлях-аргумент перевірки рішень), .claude/hooks/lesson_queue.py:463 (@import у CLAUDE.md під час підрахунку бюджету контексту), .claude/unattended/board.py:417 (файл задачі для start). Шляхи тут дає оператор або сам агент у команді чи файли самого проєкту, не відповідь моделі; петля має вже лежати в репозиторії. Наслідок — traceback замість написаної відмови скрипта; нічого не псується.
