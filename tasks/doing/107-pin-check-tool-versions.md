## Що зробити
- Що сталося 9 жовтня: о 19:46 UTC вийшов ruff 0.17.0. Двигун запускає `uvx ruff` без версії, тож сервер менш ніж за годину взяв нову версію, і tests/test_engine_lint.py почервонів на трьох hooks (I001, порядок import-ів) без жодної зміни коду, хоча в хмарі той самий commit був зелений зі старою версією. ruff 0.16 і 0.17 вимагають протилежного порядку import-ів у цих файлах: 0.16 — `tomllib` окремим блоком, 0.17 — у блоці стандартної бібліотеки. Порядок уже переставлено під 0.17.0 окремим commit-ом.
- Треба, щоб нова версія інструмента більше ніколи сама не міняла вердикт: інструменти, від яких залежить вердикт перевірок двигуна, запускаються точних версій, записаних в одному місці; сервер і хмара судять той самий commit однаково; оновлення версії — окрема задача.
- Знайди всі місця, де двигун запускає зовнішні інструменти через `uvx` або з PATH (ruff check і ruff format, mypy, vulture, pylint та інші — у tests/, hooks, gate.py, simplify_signals.py, evals), і бери версії з того одного місця. Якщо `uvx` немає, а на PATH інструмент іншої версії, перевірка не судить мовчки: або бере потрібну версію, або червоніє з поясненням. У встановлених проєктах: якщо проєкт сам задає версію інструмента, працює його версія, якщо ні — версія двигуна. Деталі вирішуй сам і запиши у звіт.
- Версії: ruff 0.17.0 (з ним код двигуна чистий); для решти — ті, з якими тести зараз зелені; запиши у звіт, які саме.
- Мінімальну версію Python двигуна передавай ruff-у як `--target-version`, щоб він сам ловив синтаксис, якого ця версія не розуміє, — так він знайшов би рядок testing.py:202 із задачі 748. Поки 748 не закрита, цього не додавай: поклади відкритий пункт.

## Готово, коли
- Жоден виклик інструмента, від якого залежить вердикт, не бере «останню» версію.
- Тест перевіряє, що версії записано в одному місці і виклики беруть їх звідти.
- Швидкий набір тестів зелений.
