# 077 — Брак тесту, знайдений overseer-ом, — окрема задача, а не BLOCK

Залежить від: —
Потрібна присутність власника: ні
Аудит потрібен: ні

## Що зробити
- Рішення власника: коли overseer знаходить лише брак тесту — «masked test gap», тобто варіант коду з помилкою, який наявні тести пропускають, або неперевірений крайній випадок, — він не блокує юніт. Юніт проходить (PASS), а overseer кладе відкритий пункт (open item) у `todo/` з точною перевіркою, яку треба дописати.
- BLOCK лишається лише для справжніх вад: заява неправдива (тести червоні, поведінка зламана, умови «Готово, коли» не виконано) або зміна щось ламає.
- Онови визначення overseer-а і все, що рахує BLOCK-и (зокрема «три BLOCK поспіль → blocked/»), так, щоб брак тесту не рахувався BLOCK-ом.
- Чому: 8–9 жовтня задачі 097 і 744 стали в `blocked/` через три BLOCK поспіль, і два з трьох у кожній були лише вимогами дописати тест на крайній випадок; робота зупинилась, хоча код був правильний.

## Готово, коли
- Вердикт overseer-а, у якому є лише брак тесту, — PASS і новий відкритий пункт у `todo/` з назвою перевірки.
- BLOCK за справжню ваду працює, як і раніше; три BLOCK поспіль за справжні вади й далі паркують задачу.
- Тести на обидва випадки; швидкий набір тестів зелений.
