# 717 — Захищений файл змінився в дереві: перевірка наприкінці ходу (варіант б із 714)

Аудит потрібен: ні
Відкритий пункт: 714-protected-file-changed-at-stop

## Що сталося
714 збудувала варіант (а): hook перед Bash відмовляє команді, текст якої пише в захищений шлях або називає секрет. Текст команди не показує шлях у змінній, шлях, складений із частин, перехід у теку й голу назву файла, запис зі скрипта, який команда лише запускає (docs/engine-limits.md, розділ про захищений шлях у команді оболонки). Варіант (б) із задачі 714 — перевірка після факту на Stop: захищений файл, що є в git (конституція, спільні налаштування, workflows, міграції), змінився в дереві за хід — ловить саме ці форми. У 714 не будувався: він не зупиняє читання секрету, діє після запису, і йому потрібне правило для законної зміни налаштувань, яку виконавець застосовує між сесіями з відповіді власника.

- Записано: 2026-10-06T06:51:26Z, агент

## Що зробити
Спершу проєкт рішення у звіті: де стоїть перевірка (gate.py шар stop чи окремий hook без зміни налаштувань), з чим порівнює (HEAD чи стан на початку ходу), як пропускає зміну, застосовану виконавцем, і що робить агент після блокування (git checkout -- файл дозволено). Негативні випадки: файл не змінювався; змінений до початку ходу власником. Будувати окремою задачею після відповіді власника, якщо проєкт її потребує.
