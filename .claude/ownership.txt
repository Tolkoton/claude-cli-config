# Who owns every path. Read by engine.py (install, update, status) and by people.
#
# Format:  <owner>  <pattern>  [seed=<file in this repository>]
#
# The FIRST rule that matches a path decides its owner, so rules go from the specific
# to the general. Patterns are anchored at the repository root: `*` stays inside one
# directory, `**` crosses directories, a trailing `/` means "this directory and
# everything under it".
#
# engine   Ships into every project. `engine.py update` replaces it there only while the
#          project has not changed it; an edited file is reported, never overwritten. (An
#          edited .claude/settings.json gains the overseer's two handlers when it lacks them.)
# project  Belongs to the project; the engine never overwrites it. With `seed=`, the first
#          install creates the file from that seed if the project lacks it — once.
#          In THIS repository the word also covers the engine's own records, tests and
#          evals: they are this repository's project data and never ship.
# machine  State of one machine and one run. Never committed, never shipped. Every install
#          writes these patterns into the project's .gitignore, and this repository's own
#          .gitignore must list them too (tests/test_ownership.py checks it).
# user     The owner's own. Personal skills (install.sh links them into ~/.claude/skills) and
#          user/settings.json, the personal settings layer (`engine.py install --personal`
#          merges it into the home settings file). Never shipped into a project.
#
# THE BOUNDARY (package 3c). `.claude/` is what defines, configures and feeds the gates —
# Claude Code protects every agent-tool write there. `.engine/` is what the agent produces
# while working — records, contracts, architecture, premises, spikes, PROGRESS — and is not
# protected. Machine state is under `.claude/state/`, written by hooks and scripts only.
