# Fixtures «Бігова група» — сцени якості задачі 501

деталей того проєкту. Ці файли можна комітити: справжніх даних тут немає.

| Файл | Що це | Пастки |
|---|---|---|
| `interview.md` | журнал розмови business analyst із власником | наголос «система розуміє, коли немає підходящого типу тижня» (п. 1) не потрапив у цілі; N3 власник підтвердив словами «Так. Це не лікар.» (п. 8); D1 обрано з варіантів business analyst в останні хвилини, і причина власника в першій версії не діє (п. 12, P3) |

| `goals-v2.md` | той самий проєкт після нового business analyst | ядро (G3, G7) зі словами власника; позначки; G4 розводить ролі; G7 — загублений наголос; N3 — причина власника; D1 — оцінки замість жалю |
| `research-note.md` | нотатка дослідника (довідкова, не рішення) | фільтр травм на кожне повідомлення; короткий строк зберігання; bandits; лист-нагадування |

| `expected.json` | що вважати добрим результатом кожної сцени | — |

Чому premise з `adr-files-on-volume.md` хибна, за документацією Cloud Run:
- один екземпляр за замовчуванням обробляє багато запитів одночасно (від 80):
  https://docs.cloud.google.com/run/docs/about-concurrency;
- після deploy якийсь час працюють дві revision, а при сплесках екземплярів буває більше за максимум:
  https://cloud.google.com/run/docs/configuring/max-instances-limits;
- Cloud Storage FUSE не блокує файли: коли кілька записів замінюють один файл, виграє останній:
  https://docs.cloud.google.com/run/docs/configuring/services/cloud-storage-volume-mounts.
