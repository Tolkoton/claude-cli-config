## Рішення

- **M1 носії замість нових записів у settings.** `settings.json` — лише для власника. Три з чотирьох механізмів їдуть на вже підключених хуках (Stop → `gate.py`, вердикти → `overseer_stop.py`, SessionStart → `env-check.sh`); все викликає один модуль, тож пізніший перехід на окремі записи змінює проводку, не поведінку.
- **M7 «наглядач перевіряє» — детермінована брама в коді**, бо пункт 0.4 забороняє цієї ночі чіпати текст наглядача. Чесне обмеження: брама така міцна, як цілісність ledger.
- **M9** запит лише після PASS.
- Усі виклики модуля з носіїв — best-effort і ловлять `TypeError/KeyError/AttributeError`: зіпсований стан не змінює вердикт жодного хука; при порожній черзі виходи gate і наглядача ті самі, що були.

## Критик (свіжий контекст) — що знайшов і що зроблено

Знайшов 2 блокуючі (збір історії; «наглядач перевіряє» без тригера) і 7 інших. Усі виправлено, крім одного дрібного, прийнятого свідомо: параметр `slice_name` у `collect_parked` не використовується (єдина сигнатура збирачів).
