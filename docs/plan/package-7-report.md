## Рішення і терміни

- **D1 лише стандартна бібліотека.** Ворота мають працювати в хмарній сесії й на машині без лінтера; лінтери — зовнішні команди. Той самий принцип, що в `complexity_budget.py`.
- **D2 обгортки зберігають імена.** `settings.json` — лише для власника; перейменування вимагало б його правки. Без `python3` обгортка Stop відмовляє (код 2): ворота, що не можуть запуститись, не рівні «перевірено».
- **D3 два словники виходу, один зміст.** CLI: 0 = немає `block`, 2 = є. З `--hook` блок Stop — `{"decision":"block","reason":…}` з кодом 0 (так працюють усі еталони й тести); `exit_code` у звіті завжди CLI-значення.
- **D4 stop — інкрементальний** (оголошена різниця, не «жодної»): `ruff` і `mypy` лише на змінених `.py`, pytest — змінені тести плюс `tests/test_<модуль>.py`. Збережено й закріплено тестами: умова `[tool.ruff]`/`[tool.mypy]` у pyproject, тести лише після чистих lint+types, `PROJECT_MARKER`, нормалізація `CODE_EXTENSIONS`, повідомлення для не-Python, три заголовки `LINT/TYPECHECK/TESTS FAILED`. **Обмеження:** помилку типів у незміненому залежному файлі або тест, зламаний модулем без «братнього» тесту, Stop не бачить — це справа `pre_commit`/`ci`; є випадок-обмеження `l-stop-misses-committed-type-error` і його двійник `d-ci-committed-type-error`.
- **D5 лічильник (виправлено після критика).** Claude Code ставить `stop_hook_active` на зупинці після блоку, тож ворота, що завжди виходять на цьому прапорі, ніколи не дорахують до N. Тепер: прапор читається першим і завершує роботу лише коли лічильник цієї сесії = 0 (зупинка, спричинена чужим хуком, повторно не перевіряється — сценарій `vs-stop-hook-active-guard` лишився `allow`); при лічильнику > 0 повторний вхід перевіряється. Лічильник за `session_id`. На N-му блоці підряд (за замовчуванням 3 — «три різні виправлення» з правил) ворота дозволяють завершити хід, дописують PARKED-запис (`Class: human-input`) у `.engine/overseer/parked.md`, видають `systemMessage` і рахують заново.
- **D6/D7 захист читає синтаксис, не текст.** Коментарі — з токенайзера, мітки skip/xfail — з AST, налаштування — з розібраних таблиць `[tool.ruff]`/`[tool.mypy]` (переформатування й коментар не спрацьовують), `project.env` — за розібраними значеннями. Рядок чи docstring, що лише згадує `# type: ignore`, — не знахідка (випадок-пастка в тестах і в золотому наборі). Обґрунтування: `gate-allow: <причина>` (≥ 12 символів, ≥ 2 слова) у тому ж рядку або в рядку-коментарі прямо над ним; для конфіга — у будь-якому доданому рядку; або рядок `gate-allow: <вид|шлях> — <причина>` у контракті зрізу, **лише поки контракт запечатаний і незмінений** (відбиток `.claude/state/contracts/<slug>.sha256`), бо інакше сторона, яку суджено, сама собі видала б дозвіл.
- **D8 чому два скрипти лишились окремо.** Обидва читають контракт зрізу, мають власний стан і перемикач (`COMPLEXITY_GATE`), жоден не лінтує файл; `contract_fingerprint` ще й стереже `/plan-slice`. Влиття поклало б розбір контракту на гарячий шлях кожного виклику й зробило б один файл власником чотирьох турбот. Спільне — формат (`record_findings`). Два Stop-хуки йдуть паралельно, тому кожен пише у свій `<source>-report.json`, а `last-report.json` належить лише `gate.py` (спільний файл гонився б). Вартість повернення: низька.
- **D11 post_write.** Точна поведінка форматера збережена (FORMAT_CMD, uv/poetry/ruff/black, jq лише для JSON — без jq файл не чіпається, prettier, `--force-exclude`). Якщо проєкт має власний FORMAT_CMD для розширення — нашого ruff-lint зверху немає.
