## Зроблено — усі сім пунктів

1. **Дошка.** `tasks/` з теками `todo/ doing/ blocked/ done/` і `README.md`. Належить проєкту:
   сідається один раз у будь-який проєкт, оновлення двигуна її не чіпає.
2. **Шаблон задачі** `tasks/TEMPLATE.md` — у тому самому вигляді, яким написані ваші задачі.
3. **Правила для агента** — чотири рядки в правилах двигуна, докладно в `tasks/README.md`.
4. **Платні прогони.** Скрипт аудиту відмовляє, якщо в задачі з `doing/` немає «Аудит потрібен:
   так»; для вашого ручного запуску — `--owner-approved`.
5. **Виконавець** `.claude/unattended/board-runner.sh`: бере задачі по одній у свіжій розмові,
   підтягує гілку, забирає вхідні, повертає задачі з відповідями, продовжує після зупинки, чекає
   ліміт, рахує вартість, пушить, зупиняється з підсумком. Стан — у `.claude/state/board/`.
6. **Ваші сімнадцять задач** лежать у `tasks/todo/` дослівно. Перша в черзі — 001.
7. **Жива перевірка пройшла:** задача `000-перевірка` пройшла `todo → doing → done` зі звітом
   через справжній `claude` за 35 секунд і **0,28 долара з 3**.

## Що варто знати

- **Жива перевірка — це найменша можлива задача.** Продовження розмови, очікування ліміту і
  справжній push на `origin` перевірені лише на підробленому `claude`. Першим справжнім
  випробуванням буде задача 001.
- **Додано понад вимоги, бо без цього не працювало б:** стеля витрат на задачу
  (`BOARD_MAX_USD`), прапорці `--once`, `--no-push`, `--retry`, `--status`, і відповідь через теку
  вхідних (заповнений файл із номером задачі з `blocked/`).
- **Запобіжник платних прогонів зупиняє недогляд, а не намір:** файл задачі агент може
  відредагувати, і це буде видно в diff.
- **Повний набір тестів став довшим** — близько чотирьох хвилин замість двох: тести виконавця
  ганяють його сорок разів на синтетичних репозиторіях.
- **Критик двічі читав план:** REVISE (ліміт у 3 долари не мав механізму), потім PASS.
- **Зрізи будувались без окремого плану на кожен** і без аудиту наглядача по ходу; аудит
  усього пакета запитано наприкінці.
