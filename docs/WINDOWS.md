# Windows через WSL2

На Windows двигун працює всередині WSL2 — це Linux (Ubuntu), який Windows запускає поруч із собою.
Усередині WSL2 двигун поводиться так само, як на звичайному Linux: ті самі hook-и, gates, runner і
task board, жодних окремих налаштувань. Нативну Windows (Git Bash, PowerShell, cmd) двигун не
підтримує: hook-и — це bash-скрипти, і перевіряються вони лише на Linux і macOS.

Налаштування займає пів години і робиться один раз. Потрібні Windows 10 (версія 2004 або новіша)
чи Windows 11 і права адміністратора на першому кроці.

**Головне правило:** усе — проєкт, git, Claude Code, двигун — живе всередині Ubuntu. З боку Windows
лишається тільки вікно: термінал і, за бажанням, VS Code.

## 1. Встановити WSL2 та Ubuntu

Відкрийте PowerShell від імені адміністратора (меню «Пуск» → наберіть `PowerShell` → «Запуск від
імені адміністратора») і виконайте:

```powershell
wsl --install
```

Команда вмикає WSL2 і ставить Ubuntu. Перезавантажте комп'ютер, коли вона попросить. Після
перезавантаження відкриється вікно Ubuntu і попросить вигадати ім'я користувача Linux і пароль —
вони не пов'язані з вашим обліковим записом Windows; пароль знадобиться для `sudo`.

Перевірте, що це саме друга версія (знову в PowerShell):

```powershell
wsl -l -v
```

У стовпці `VERSION` навпроти Ubuntu має стояти `2`. Якщо там `1` — `wsl --set-version Ubuntu 2`.
Якщо `wsl --install` каже, що WSL уже встановлено, але Ubuntu немає, — `wsl --install -d Ubuntu`.

Далі всі команди — у терміналі Ubuntu (меню «Пуск» → `Ubuntu`, або вкладка Ubuntu у Windows
Terminal), не в PowerShell.

## 2. Поставити інструменти в Ubuntu

```bash
sudo apt update
sudo apt install -y git jq python3 curl
```

- `git` — без нього hook-и не бачать ні гілки, ні змін.
- `python3` — на ньому написані gates, overseer і task board.
- `jq` — ним hook-и читають те, що їм передає Claude Code (без нього вони обходяться `python3`).

`uv` потрібен лише тоді, коли ваш проєкт на Python і має файл `uv.lock`. Встановлювач завантажте,
перегляньте і тоді запустіть:

```bash
curl -LsSf https://astral.sh/uv/install.sh -o /tmp/uv-install.sh
less /tmp/uv-install.sh
sh /tmp/uv-install.sh
```

Закрийте й відкрийте термінал, щоб `uv` з'явився в PATH. Проєкт на Node.js, Go чи Rust потребує
свого інструментарію — ставте його так само, всередині Ubuntu, як на будь-якому Linux.

## 3. Налаштувати git

```bash
git config --global user.name "Ваше Ім'я"
git config --global user.email "you@example.com"
git config --global core.autocrlf input
```

Останній рядок важливий: з `core.autocrlf true` git переписує закінчення рядків на віндовські
(CRLF), а bash-скрипт із такими рядками не запускається — hook-и падають з помилкою
`bash\r: No such file or directory`. Значення `input` лишає файли такими, як вони є в репозиторії.

Доступ до GitHub налаштуйте теж усередині Ubuntu: SSH-ключ (`ssh-keygen -t ed25519`, публічний
ключ `~/.ssh/id_ed25519.pub` додайте у свій профіль GitHub) або `gh auth login`. Ключі й паролі,
збережені у Windows, звідси не видно.

## 4. Покласти проєкт у домашню теку Linux

```bash
mkdir -p ~/projects
cd ~/projects
git clone git@github.com:ваша-організація/ваш-проєкт.git
```

Не тримайте проєкт на диску Windows — тобто в `/mnt/c/...`, `/mnt/d/...` (так із Ubuntu видно
диски `C:`, `D:`). Там кожна команда git і кожен прогін тестів у рази повільніші, а права файлів
не зберігаються: hook-и втрачають позначку «виконуваний», і git показує файли зміненими, хоча їх
ніхто не чіпав. Якщо проєкт уже лежить на диску Windows — склонуйте його заново в `~/projects/`,
а не копіюйте теку.

Дістатися до файлів проєкту з Windows можна завжди: у Провіднику наберіть в адресному рядку
`\\wsl$\Ubuntu\home\<ваше ім'я в Linux>\projects`, або в терміналі Ubuntu виконайте `explorer.exe .`.

## 5. Встановити Claude Code всередині WSL2

Claude Code ставиться в Ubuntu, не у Windows. Встановлювач завантажте, перегляньте, запустіть:

```bash
curl -fsSL https://claude.ai/install.sh -o /tmp/claude-install.sh
less /tmp/claude-install.sh
bash /tmp/claude-install.sh
```

Актуальний спосіб — в офіційній інструкції: <https://code.claude.com/docs/en/setup>. Закрийте й
відкрийте термінал, тоді перевірте:

```bash
which claude
```

Шлях має починатися з `/home/...`. Якщо він починається з `/mnt/c/...` — запускається Claude Code,
встановлений у Windows; він не бачить ні hook-ів, ні інструментів Ubuntu. Встановіть його в Ubuntu,
як вище. Перший запуск `claude` попросить увійти — посилання відкриється у браузері Windows.

## 6. Встановити двигун у проєкт

```bash
cd ~
git clone git@github.com:Tolkoton/claude-cli-config.git
python3 ~/claude-cli-config/engine.py install ~/projects/ваш-проєкт
```

Далі — як на Linux: `docs/TEMPLATE-SETUP.md` веде по налаштуванню `.claude/project.env` крок за
кроком. Перевірте результат і запустіть Claude Code:

```bash
cd ~/projects/ваш-проєкт
git status
claude
```

## 7. Перевірити, що все на місці

На початку кожної сесії двигун сам оглядає машину (hook `env-check.sh`). Якщо все гаразд, він
мовчить. Якщо ні — у перших рядках сесії буде один із двох списків:

- **«missing on this machine»** — бракує інструмента (`git`, `python3`, `jq`, `uv`…): поверніться
  до кроку 2;
- **«WSL»** — одна з двох пасток: проєкт лежить на диску Windows (крок 4) або git переписує
  закінчення рядків (крок 3).

Запустити перевірку руками, з теки проєкту:

```bash
bash .claude/hooks/env-check.sh
```

Порожній вивід означає «нічого не бракує».

## VS Code

VS Code ставиться у Windows, а працює з файлами всередині Ubuntu.

1. Встановіть VS Code у Windows і в ньому — розширення **WSL** (від Microsoft).
2. У терміналі Ubuntu зайдіть у проєкт і відкрийте його:

   ```bash
   cd ~/projects/ваш-проєкт
   code .
   ```

3. Унизу ліворуч у вікні VS Code має стояти `WSL: Ubuntu`. Якщо цього напису немає, ви відкрили
   теку з боку Windows: закрийте вікно й повторіть крок 2.
4. Термінал усередині такого вікна (`` Ctrl+` ``) — це термінал Ubuntu: `claude` запускайте в ньому.
   Розширення, яким потрібен доступ до коду (Python, Claude Code та інші), VS Code запропонує
   встановити «in WSL: Ubuntu» — погоджуйтеся.

Не відкривайте проєкт через «File → Open Folder» зі шляхом `\\wsl$\...` і не редагуйте його
віндовськими програмами, що самі міняють закінчення рядків.

## Типові пастки

| Що бачите | Причина | Що зробити |
|---|---|---|
| git і тести дуже повільні; `git status` показує змінені файли, яких ви не чіпали | проєкт на диску Windows (`/mnt/c/...`) | склонувати проєкт у `~/projects/` (крок 4) |
| hook падає з `bash\r: No such file or directory` | git переписав закінчення рядків | `git config --global core.autocrlf input`, потім склонувати проєкт заново |
| hook-и не спрацьовують, `which claude` показує `/mnt/c/...` | запускається Claude Code із Windows | встановити Claude Code в Ubuntu (крок 5) |
| `wsl -l -v` показує `VERSION 1` | стара версія WSL | `wsl --set-version Ubuntu 2` |
| нічний прогін runner-а обірвався | Windows заснула або вимкнула WSL, коли закрили останнє вікно Ubuntu | див. нижче |

## Runner на Windows

Працювати з Claude Code в інтерактивній сесії у WSL2 можна без обмежень. З runner-ом, який бере
задачі з task board без вас, є одна особливість: WSL2 живе, доки працює Windows і відкрите хоча б
одне вікно Ubuntu. Коли комп'ютер засинає чи перезавантажується для оновлення, runner зупиняється
разом із ним; незакомічена робота поточної задачі лишається в робочому дереві, і наступний запуск
runner-а її продовжує. Для прогонів на всю ніч надійніший окремий сервер на Linux.

## Що перевірено, а що ні

Розпізнавання WSL і обидві пастки перевіряє набір тестів `tests/test_env_check.py` — на підроблених
ознаках (рядок ядра з `/proc/version`, шлях проєкту, налаштування git), на Linux. На справжній
машині з Windows цю інструкцію поки що ніхто не пройшов від початку до кінця: якщо якийсь крок у вас
пішов інакше — це задача для task board.
